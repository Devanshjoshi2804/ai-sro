## The conditional-required-field trap

`Customer Type` has **no asterisk** on the form, but Save fails if it's blank **and** either
`Cross Dock Order Lines` or `Pallet Building` is left at its default "Inherit from customer
type". The error:

> Customer Type field is mandatory when Cross Dock Order Lines/Pallet Building field is Inherit
> from customer type

**This error dialog did not appear in any accessibility-tree snapshot**, despite being a real,
correctly-positioned, modal DOM element. It left an invisible page-covering mask that silently
absorbed two subsequent Save clicks with zero symptoms — no error, no request, nothing. Found
only by querying `Ext.ComponentQuery.query('[floating]')` directly. See
`../../KNOWLEDGE-BASE.md` §4 for the general-purpose detection method — **any automation clicking
Save on this app must check for this class of failure, not just watch for a visible dialog.**

Fix: set `Customer Type` to any valid code before Save (valid codes come from the combobox's
bound store — set programmatically via `Ext.ComponentQuery.query('combobox[fieldLabel="Customer Type"]')[0].setValue('DUM')`
if typing doesn't register cleanly).

## Verified write operations

(create cascade), `DELETE customers/{id}` + `DELETE addresses/{id}` (reverse-order delete).

## Failure cases (retrofitted 2026-08-12)

1. The conditional-required-field trap above (invisible mask, Save silently absorbs clicks) is
   the primary documented failure mode for this screen.
2. **Duplicate Customer number is a client-side gate**, like Customer Types — filling the form
   with a real existing customer number (`0000000040`) plus a valid Customer Type and Client
   keeps Save permanently disabled with a red icon on the Customer field; confirmed via network
   capture that zero requests fire. This is the fourth distinct duplicate-key validation pattern
   found across the five sibling Partners screens tested this pass — see `clients.md`'s Failure
   cases section for the full comparison table across Customer Types / Suppliers / Clients /
   Existing Customers. Do not assume any one screen's validation architecture (client vs server,
   atomic vs not) applies to another, even in the same nav group.
