# Pick Settings

You use the pick settings to configure the attributes and behavior for picking inventory using a radio frequency (RF) terminal or a workstation. These configurations only apply to equipment-mounted and portable RF devices and manual pick confirmation.

To configure the attributes and behavior for picking inventory using a voice device, see [Voice Picking](voice-picking.md).

## Configure pick settings

1.  Select **Configuration > Outbound > Picking > Pick Settings**.
2.  Enter information in the [Pick Settings fields](#Pick__Settings_fields).
3.  To define the label strategy policies that determine the level of UCC-128 labeling to use:
    
    1.  Click **Label Strategy**.
        
    2.  Perform one of the following tasks:
        
        -   To add a policy value, click **Add**.
            
        -   To modify a policy value, in the grid, click the value.
            
    3.  Select and define a **Policy Value**:
        
        -   **DEFAULT-STRATEGY**: Defines the default UCC-128 labeling strategy to use if a strategy is not defined for a batch. The value you enter in the **Value 1** field for this policy value should match one of the names (**Value 1**) defined for a STRATEGY-LIST policy. When the DEFAULT-STRATEGY is used, the application finds the STRATEGY-LIST with matching names (for example, DEFAULT), and then uses the strategy defined in **Value 2** for that STRATEGY-LIST policy. **Value 2** is not defined for the DEFAULT-STRATEGY policy.
            
        -   **DETERMINE-STRATEGY-BY**: Defines the method by which the strategy for labeling pick work is determined. For this policy value, you can enter one of the following values in the **Value 1** field (**Value 2 is** not defined for this policy value):
            
            -   **lodlvl**: Indicates that the LPN level will be used as the labeling strategy for the pick work.
                
            -   **column name from the pick work or ship detail table**: Indicates the column name that is used as the labeling strategy for the pick work.
                
        -   **STRATEGY-LIST**: Defines a UCC-128 labeling strategy. For this policy, the Value 1 field value is a name generated by the DETERMINE-STRATEGY-BY policy value, indicating the name for the UCC-128 labeling strategy defined in the **Value 2** field. The following values are valid entries for **Value 2**:
            
            -   **L**: LPN (pallet) UCC-128 labeling is used.
                
            -   **S**: Sub-LPN (case) UCC-128 labeling is used.
                
            -   **N**: UCC-128 labeling is not used.
                
    4.  Click **Save**.
        
4.  To define the manufacturer ID policies that control the creation of the serialized portion of the UCC-128 label for the manufacturer:
    
    1.  Click **Manufacturer ID**.
        
    2.  Perform one of the following tasks:
        
        -   To add a policy value, click **Add**.
            
        -   To modify a policy value, in the grid, click the value.
            
    3.  Select and define a **Policy Value**:
        
        -   **DEFAULT-ID**: Defines the default manufacturer ID that is used if one is not defined for a batch. The value you enter in the **Value 1** field for this policy value should match one of the names (**Value 1**) defined for a LIST-ID policy. When the DEFAULT-ID is used, the application finds the LIST-ID with matching names (for example, DEFAULT), and then uses the data defined in that policy value. **Value 2** and **Value 3** are not defined for the DEFAULT-ID policy.
            
        -   **DETERMINE-ID-BY**: Defines the method by which the serialized portion of the label is created. The **Value 1** field for this policy is a column name from the pick work or ship detail table, indicating the code that is used when creating the serialized portion of the UCC-128 label for the manufacturer.
            
        -   **ID-LIST**: Defines a strategy for generating a manufacturer ID. For this policy, the following values are defined:
            
            -   **Value 1**: Name generated by the DETERMINE-ID-BY policy value, indicating the name for the manufacturer ID identified in the **Value 2** field.
                
            -   **Value 2**: Sequence value supported by the application control table used to generate the serialized portion of the UCC-128 label for the manufacturer.
                
            -   **Value 3**: Character string that identifies the manufacturer.
                
    4.  Click **Save**.
        
5.  Click **Save**.

## Pick Settings fields

 
| Field | Description |
| --- | --- |
| Prompt for Barcode at Pick Confirmation | If Yes, then when a user opens the Pick Confirmation page to manually confirm picks, the application prompts the user to scan or enter a barcode to specify the picks to confirm. However, the operator is not required to enter a value to proceed. The barcode value can be a carton number, a work assignment, or a work reference. If set to Yes, then after a barcode is entered, the Confirm Picks window is displayed and populated with the pick information.<br > If No, then when a user opens the Pick Confirmation page, the application does not prompt the user to scan or enter a barcode. The user can either enter search criteria or select a quick filter to view pick information, or manually display the prompt to scan a barcode. |
| User Chooses Next LPN to Deposit | If Yes, after picking, the operator is allowed to either accept the displayed LPN to deposit or enter a different one.<br > If No, the operator must deposit the displayed LPN. |
| Confirm Sub UCC Label at Picking | If Yes, when the operator picks a case that requires a UCC-128 label, the operator must confirm (scan) the label number and apply the label to the case during the pick. UCC-128 numbers are used to identify the contents of a case, and to send out advanced shipment notifications (ASNs) to external applications. Prior to beginning a picking tour, the application verifies whether there are picks that require a UCC-128 label; if so, the operator can print the labels and begin picking. When the operator picks a case that requires a label, the RF Subucc Confirmation screen is displayed, and the operator must scan the UCC-128 label to confirm the label is valid for the picked case. This confirmation is valid for outbound orders or replenishments that require cases and are picked individually or as part of a pick list.<br > If No, the operator can still print the UCC-128 labels prior to picking, but the application does not validate whether the correct label is applied to a case. |
| Display Order Information at Picking | If Yes, the Order Details Display screen is accessible to the operator during picking. The order details information includes the customer, order, item, carrier, shipment, stop, and load for which the pick is required. If notes exist on the order, the order information is displayed before the notes are displayed.<br > If No, the Order Details Display screen is not accessible to the operator. However, if available, the operator can still view order notes. |
| LPN Preparation | Determines the point during outbound order processing when the Load Preparation screen is displayed to the operator. The Load Preparation screen displays the handling unit type and LPN attributes that must be applied to the inventory before it is loaded onto transport equipment.<br>-   • **Deposit**: Displays the screen after a selection is made on the Product Deposit screen.
<br>-   • **Picking**: Displays the screen during a pick after the item has been confirmed.
<br>-   • **Picking and Deposit**: Displays the screen after each pick is completed and after a selection is made on the Product Deposit screen. |
| UCC Installed | If Yes, then UCC-128 processing is enabled.<br > If No, then UCC-128 processing is not enabled. |
| Confirm Each Sub-UCC | If Yes, then each pick work entry for a sub-level UCC-128 label will be generated with a different cmbcod, allowing the picks to be confirmed individually.<br > If No, then all pick work for a sub-level UCC-128 label will be generated with the same cmbcod, allowing the picks to be confirmed in one batch. |
