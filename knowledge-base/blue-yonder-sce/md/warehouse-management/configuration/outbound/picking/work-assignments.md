# Work Assignments

A work assignment is a picking process by which the application combines individual picks into a work assignment that an operator can perform in one picking tour, moving from one pick location to another until the assignment is complete. With work assignments, the operator does not have to deposit the inventory to its destination location after each pick; instead the operator performs all picks, which can include cartonized (cluster) picks, bulk picks, and starter pallets, and then deposits the picked inventory to the destination location.

When you configure work assignments, you define the following attributes:

-   Starter pallet options. A starter pallet is a major quantity pick that provides a base for a less than full pallet picking tour. Since it is typically the first pick in a pick tour, it creates an LPN platform for subsequent picks in the tour. This approach eliminates having to hand-stack smaller UOMs on a new LPN. See [Starter pallets](#Starter_pallets).
-   Work assignment rules. For a work assignment rule, you define the following attributes:
    
    -   Type of picks in the work assignment
    -   Type of work that is created to perform the picks
    -   How pick work is resumed or passed to another picker
    -   Order in which the picks are listed on the work assignment
    -   Criteria used to select picks for inclusion on work assignments generated by the rule
    -   Criteria that determines which picks can be included in the same work assignment
    -   Sequence in which candidate picks are ordered before being added to a work assignment
    -   Attributes and criteria that determine the capacity of a work assignment
        
    
    See [Work assignment rules](#Work_assignment_rules).
    
-   Order sequence processing attributes. Order sequence processing is a process for picking and shipping inventory for the same item family (or item family set) for multiple orders in a sequenced fashion. The sequence matches the order in which the items are required at a production line for the assembly of a top-level item (such as an automobile). See [Order sequence processing](work-assignments/order-sequence-processing.md).

## Work assignment rules

A work assignment rule is a reusable, named configuration that can be used individually or in combination with other work assignment rules (as a work assignment rule group) to generate one or more work assignments. Multiple work assignments can result from a single work assignment rule if the number of picks exceeds the capacity of a single work assignment.

Work assignment rules are required for the application to create work assignments and release inventory for picking. You can execute a rule or rule group manually in Pick List Operations, or automatically by configuring timer-based or schedule-based jobs (based on the PICK-RELEASE-MANAGER job) in the Console under Jobs.

When you configure a work assignment rule, you must define criteria for the following processes:

-   **Pick Order**: Determines the order in which picks will be performed for a work assignment. You select the attributes to use (such as location travel sequence) and place them in the sequence to be used. The pick order that you define should be different from the criteria selected for Criteria Grouping.
-   **Selection Criteria**: Determines which picks are eligible to be included in work assignments based on the rule. For example, you can limit the list of eligible picks to those for a specific client, customer, and order type.
-   **Criteria Grouping**: Determines which picks can be included in the same work assignment. You select the attributes that must match for picks to be included. For example, you can limit a work assignment to picks for the same shipment and item family. The sequence in which the selected attributes are arranged is the sequence in which they are processed; for example, first by shipment and then by item family.
-   **Criteria Sequence**: Determines the order in which picks are sorted before being added to a work assignment. For example, you can select the item weight class and define the sort order such that heavier items are added to the work assignment first.
-   **Break Value**: Determines the capacity of a work assignment based on the selected group break functions (count, volume, weight, and pick quantity). For example, you can limit capacity by Count, select the field to limit, and then enter a maximum quantity for the field.
    
    **Note**: If an operator splits a carton during a work assignment, the remaining picks assigned to the new carton are typically added to the existing work assignment. However, if the work assignment rule has a break value of Count and the group break criteria includes Cartons, then the remaining picks are added to a new work assignment if the new carton exceeds the maximum cartons allowed.
    
    As a further example, you can set the LPN limit to match a warehouse equipment limit so that each work assignment can be picked in full and delivered to the destination location at once. Or you can set the LPN limit to the number of pallets an RF operator can pick and deposit in the average amount of time in which you want work assignments complete. If an RF operator can pick and deposit 30 pallets in an hour, but you want all work assignments completed in approximately 30 minutes, then you would set the maximum value to 15.
    
    **Notes**: 
    
    -   If you specify more than one break value, the application uses the lowest capacity value to limit the work assignment so it does not violate any break values. For example, if one break value defined a maximum count of orders as 1, and another break value defined a maximum volume, then the application will not add picks for more than one order to a work assignment, even if the pick volume is below the maximum volume break value.
    -   If you specify a handling unit type for the work assignment rule and also define a break value using the weight or volume group break function, the application uses the value that represents the lowest capacity. For example, if the selected handling unit type has a maximum of 5,000 cubic inches and the maximum volume break value is 5 cubic feet (8,640 cubic inches), then the application uses the handling unit type capacity instead of the break value maximum for work assignments created with the rule.
    

## Work assignment rule break values

You can define a break value for a work assignment rule. The break value defines the capacity of the work assignment generated by the work assignment rule. If the work assignment rule is for slots on a master handling unit, the break value defines the capacity of the slot.

The following examples illustrate the use of a break value in relation to handling units:

-   Slot on a master (slotted) handling unit
    
    If the rule is configured for a slot, the rule applies to the capacity of the slot. For example, assume you have an order for 250 quantity, a master handling unit with 3 slots (slot handling units), and a rule for the slots with a break value set to Pick Quantity = 100. The pick work will be split into 100 quantity in each of the first two slots and 50 in the last slot, and all pick work will be on the same work assignment.
    
-   Master (slotted) handling unit
    
    If the rule is configured for a master handling unit, the rule applies to the whole work assignment. For example, assume you have an order for 250 quantity, a master handling unit with 3 slots (slot handling unit type), and a rule for the master handling unit type with a break value set to Pick Quantity = 100. The pick work will be split into 3 work assignments, with 100 quantity for each of the first two work assignments and 50 in the last work assignment.
    
-   Handling unit that is not a master or a slot on a master
    
    If the rule is configured for a regular handling unit (not a master or a slot), the break value applies to the whole work assignment. For example, assume you have an order for 250 quantity, and a rule for the handling unit with a break value set to Pick Quantity = 100. The pick work will be split into 3 work assignments, with 100 quantity for each of the first two work assignments and 50 in the last work assignment.
    

## Work assignment rule groups

A work assignment rule group is a set of rules that you want the application to apply all together. When a rule group is executed, the application processes the rules in the group sequentially, using the results of the first rule to process the second, and so on. The following examples show how rule groups can be used:

-   Build larger, more optimal work assignments from a variety of smaller cube work assignments
-   Generate separate work assignments for large orders of an item family that require one item in the family to be shipped separately
-   Generate a work assignment for multiple orders that directs the picker to place each order to a separate slot on a handling unit

For a rule group to be eligible for processing, it must be enabled.

## Work assignment setup

You must perform the following tasks to configure the application to create pick work assignments.

1.  Configure work assignments. Configure the general settings, define individual rules, and if you want to process multiple rules together, organize rules into rule groups. See [Configure work assignments](work-assignments/procedures-for-work-assignments.md).
2.  Configure pick methods. A pick method is used to define the type of pick that is created when inventory is allocated and released for picking. You must configure a pick method for grouping picks into work assignments by setting the following attributes for the pick method:
    
    -   Set the **Work Assignments** field to Yes.
    -   For standard picks, set the release rule to create work using the work assignment picking operation (List Pick).
    
    See [Pick Methods](pick-methods.md).
    
3.  Configure allocation search paths. A search path identifies the source pick zone from which the application should attempt to allocate inventory based on the attributes of the required inventory. A search path rule defines the pick zone from which inventory can be allocated and the pick method for releasing pick work from the pick zone. Assign the pick method that you created for work assignments to the search path rules for pick zones in which work assignment picking is performed. See [Allocation Search Paths](../allocation/allocation-search-paths.md).
4.  Configure pick zones. Configure the pick zones in which you want the list of work assignment picks to be displayed to the operator. Visibility to the picks allows the operator to perform the picks out of sequence. This is useful in situations where, because of the picking equipment that is used, it is more efficient to perform the picks in reverse order. See [Pick Zones](../allocation/pick-zones.md).
5.  Configure handling units. If you want to assign a handling unit type to a work assignment, or if you want to pick to specific slots on a handling unit, then configure the following attributes on the handling unit type configuration page:
    
    -   Configure the work assignment attributes.
    -   Select the types of cartons that can be placed on a handling unit type.
    -   For handling units, such as a trolley, that are used to transport other handling units (slots), define the handling unit slots to which inventory can be picked.
    
    See [LPN Handling](../../inventory/lpn-handling.md).
    
6.  Configure cartons. If you allow cartonized picks to be included in work assignments, then for each type of carton that is used for work assignments, enable it for work assignments and specify the point at which carton labels are printed. See [Pick Cartonization](pick-cartonization.md).
7.  Configure the weight class for items. If you want to order picks on a work assignment by weight code, for example so that heavier items are picked first, then define the following attributes:
    -   Define or use the default weight codes, and assign a sequence number to each weight code. The sequence number determines how the code value is sorted in the work assignment. For example, you can define a code value of Heavy with a sequence number of 0 to ensure that heavy items are picked before items with other code values in the list.
    -   Assign a weight code to each item that you want to sort this way. See [Items](../../inventory/items/items.md). You can also updated multiple items at the same time.
8.  Configure operations. Select the users and equipment that are authorized to perform the work assignment (List Pick) operation. See [Work Operations](../../work/work/work-operations.md).
9.  Configure the job for work assignment generation. You use the Jobs option accessible from the Console to configure the PICK-RELEASE-MANAGER job. You can configure the job for a timer-based or schedule-based execution of work assignment rules and rule groups. Alternatively you can copy this job and configure a different schedule for it, and then add to the command the rule or rule group that you want it to execute.
    
    A rule can be associated with multiple jobs. To specify rules or rule groups, you must change the command argument to include the name of the rule or rule group. The following examples list the command arguments that can be used:
    
    -   To execute a single rule configuration, use: pcklst\_rule\_set\_name, wh\_id, client\_id
    -   To execute all the rules assigned to a specific rule group in sequence, use: pcklst\_rule\_grp\_name, wh\_id, client\_id
    -   To execute all the enabled rule groups configured for the warehouse, use: wh\_id

## Work assignment setup for picking to slots

You can configure work assignment rules to direct an operator to pick to slots, such as totes on a trolley or holes in a dividing wall.

**Note**: To configure work assignment rules to direct picking to handling unit slots on a handling unit, see [Handling unit slots setup tasks](../../inventory/lpn-handling/handling-unit-slots-setup-tasks.md).

To configure work assignments to direct picking to slots that are not associated with a handling unit, you must perform the following tasks to configure a work assignment rule for the slot (such as the totes on a trolley or slots in a dividing wall) and a work assignment for the master (such as the trolley). See [Add or modify work assignment rules](work-assignments/procedures-for-work-assignments.md).

1.  Configure a work assignment rule for the slot with the following attributes:
    -   For the **Pick Tasks on Existing Work Assignments** field, select Yes to ensure that the application considers as many same-item picks together as possible.
    -   For the **Assign Slot** field, select No. This field is set to Yes on the work assignment rule for the master, but must be set to No for the slot rule.
    -   For the **Selection Criteria**, define the criteria that determines which picks can be considered for inclusion on the work assignment for the slots, such as by item family.
    -   For the **Criteria Grouping**, select the attributes that determine which picks can be included on the same work assignment for the slots, such as by order number.
    -   For the **Criteria Sequence**, select the attributes that determine the order in which picks are sorted before being added to a work assignment for the slots, such as by item number.
    -   For the **Break Value**, configure the attributes that define the capacity of the work assignment for the slots, such as one order per slot.
2.  Configure a work assignment rule for the master with the following attributes:
    -   For the **Assign Slot** field, select Yes. Selecting Yes directs the application to assign a slot number to each pick when work assignments are generated by this rule. This is required to direct the operator to deposit inventory to the slot number associated with the pick.
    -   For the **Selection Criteria**, configure the rule to consider for inclusion all the picks that meet the criteria defined by the slot work assignment rule. For example, if you created a slot work assignment rule called TOTE1, then configure the master rule as follows: Table Name = Pick List, Field Name = Pick List Rule Name, and Value = TOTE1.
    -   For **Criteria Grouping** and **Criteria Sequence,** select the same values that you defined for the slot work assignment rule.
    -   For the **Break Value**, configure the capacity of the work assignment by the number of slots. For example, if a trolley (master) contains 6 totes with one order per tote, then configure the group break criteria for the master work assignment as follows: Break Value = Count, Group Break Field = Orders, Maximum Quantity = 6.
3.  Create a work assignment rule group that includes the master work assignment rule and the slot work assignment rule. The rule group enables you to run a number of rules together in order so that the results of first rule are considered when the second rule is running, and so on.
    
    When you define the rule group, arrange the sequence so that the slot rule is executed first, and then the master rule. When the rule group is executed, it will create a single work assignment that will direct the operator to pick quantities to the individual slots.
    
    See [Configure work assignment rule groups](work-assignments/procedures-for-work-assignments.md).
    

## Work assignment processing

The following steps describe the process that occurs when a work assignment is generated either automatically by the application or manually be a user:

1.  After work assignment picks are released, the application assigns the Ready for List status to all of the picks that can be assigned to a work assignment. The application builds the work assignments based on the rules and rule groups that were executed.
2.  If Inventory handling unit tracking is enabled, the application assigns a handling unit type to a work assignment, using the handling unit defined on the order line or for the customer or customer type, in that order of precedence.
    -   If a handling unit type is specified on the work assignment rule, then the work assignment only includes picks with the same handling unit type or no handling unit type. The restrictions defined for the handling unit type (or the minimum value of weight, volume, or count defined for the rule) will be considered while generating the work assignment and the handling unit type that is used.
    -   If a handling unit type is not specified on the work assignment rule, then picks with or without handling unit types defined will qualify for the work assignment, but picks with different handling unit types are assigned to separate work assignments.
    -   When the application generates a work assignment based on a handling unit type, the operator who performs the picks is directed to pick up a handling unit, and then pick inventory to the handling unit.
    -   If a handling unit slot is assigned to a work assignment, then the operator is directed to pick to the specific slot on the handling unit type designated for the pick.
3.  If Inventory handling unit tracking is not enabled, the operator is not directed to pick to a specific handling unit type; instead, the operator selects the handling unit type and enters an LPN on which to place the picks.
4.  When work assignment picks are released, an operator can perform the following tasks:
    -   Sign on to one or more work assignments
    -   Pick part of a work assignment, sign off the assignment, and then sign back on to it at a later time and resume picking the rest of the assignment
    -   Stop working on a work assignment at any point, and allow incomplete picks to go back to the work queue to be picked by another operator
    -   Override the handling unit type assigned to the work assignment
    -   View a summary of remaining picks on the work assignment
    -   Obtain a printed report to use for paper-based work assignment picking
    -   Split a carton (For example, if inventory cannot fit into its designated carton, an additional carton may be needed to complete the remaining picks.)
        
        **Note**: If an operator splits a carton during a work assignment, the remaining picks assigned to the new carton are typically added to the existing work assignment. However, if the work assignment rule has a break value of Count and the group break criteria includes Cartons, then the remaining picks are added to a new work assignment if the new carton exceeds the maximum cartons allowed.
        

## Work assignment rule references

A work assignment rule reference is an attribute that can be assigned to a shipment to override a base work assignment rule that would normally be used to build work assignments for the shipment. A work assignment rule is a reusable, named configuration that can be used individually or in combination with other work assignment rules (as a work assignment rule group) to generate one or more work assignments. Occasionally, you may need to use a work assignment rule reference to override a base rule for a specific shipment to accommodate operational requirements.

The work assignment rule reference is a value that is not only assigned to a shipment, but it is included as selection criteria in the override rule. When the application executes the override rule, it uses the work assignment rule reference as selection criteria, meaning that only the shipments with the defined reference identifier are selected and included in the work assignment. For information on setting up work assignment rule references, see [Work assignment rule reference setup](#Work_assignment_rule_reference_setup).

For example, assume you have a base work assignment rule (RULE01) that splits pick tasks across assignments to maximize capacity, and that the rule has the following selection criteria:

  
| Entity | Column | Value |
| --- | --- | --- |
| Pick Work | Client ID | Client A |
| Pick Work | Route-To Customer | Customer A |

Based on the criteria, eligible picks for work assignments built from RULE01 include only those for Client A and Customer A. Now, assume that occasionally there are shipments for Client A and Customer A that require pick tasks not be split across assignments.

In this situation, you can create a duplicate work assignment rule (RULE01\_Override) and a work assignment rule reference (R01\_OVRD). The work assignment rule override includes the different configurations needed by specific shipments for Client A and Customer A; in this example, you would configure the override rule to not allow the splitting of pick tasks across assignments. Additionally, you must then add the work assignment rule reference as selection criteria in the override rule, meaning the selection criteria for RULE01\_Override includes the following attributes:

  
| Entity | Column | Value |
| --- | --- | --- |
| Pick Work | Client ID | Client A |
| Pick Work | Route-To Customer | Customer A |
| Shipment | Work Assignment Rule Reference | R01\_OVRD |

If shipments that meet the selection criteria of RULE01 exist but need to be processed using RULE01\_Override, then you can set the Work Assignment Rule Reference field on the shipments to R01\_OVRD. When the application executes the override rule, it only selects the picks that are associated with a shipment that has the defined rule reference R01\_OVRD, and then builds work assignments based on the override rule.

If you want the application to apply both rules at once, you can create a work assignment rule group. However, since the override rule is typically more specific (meant for certain shipments), it should be processed before the base rule to ensure shipments associated with the rule reference are not included in base rule processing. Therefore, the work assignment rule group selections should be in the following sequence:

 
| Sequence | Rule |
| --- | --- |
| 1 | RULE01\_Override |
| 2 | RULE01 |

Based on the group criteria, the application first builds work assignments (for Client A and Customer A) with picks for shipments that were assigned the R01\_OVRD work assignment rule reference. When there are no eligible picks remaining, the application continues building work assignments for Client A and Customer A based on RULE01.

## Work assignment rule reference setup

You must perform the following tasks to use work assignment rule references to override a work assignment rule for a shipment:

1.  Add a work assignment rule reference. The work rule reference is assigned as an attribute of a shipment and also as selection criteria for the override work assignment rule. See [Configure work assignments](work-assignments/procedures-for-work-assignments.md).
2.  Add an override work assignment rule. The override rule is typically a duplicate of an existing rule, except that it is configured to build work assignments slightly different than the base rule. You must configure the selection criteria for the override rule to include the work assignment reference (**Entity** \= Shipment, **Column** \= Work Assignment Rule Reference, and **Value** \= \[user defined reference value\]). See [Configure work assignments](work-assignments/procedures-for-work-assignments.md).
3.  To process and apply an override rule with a base rule, add a work assignment rule group that includes both rules. Sequence the rules in the group so that the override rule is applied first to ensure all the override shipment picks are planned into work assignments before the remaining eligible picks are planned using the base rule. See [Configure work assignment rule groups](work-assignments/procedures-for-work-assignments.md).
4.  Associate the work assignment rule reference with a shipment. Assuming all other selection criteria matches, for the application to use the override rule to build work assignments, the Work Assignment Rule Reference field on a shipment must match the rule reference used in the rule's selection criteria. See [Add or modify a shipment](../../../outbound-planner/outbound/procedures-for-shipments.md).

**Note**: You can create a new work assignment rule reference when you add or modify a shipment, but the application does not process an override rule for the shipment unless the rule reference is included as selection criteria for the override rule. See [Work assignment rule references](#Work_assignment_rule_references).

## Work assignments picked to sub-LPNs

You can configure a work assignment rule so that work assignments created from that rule are picked to a sub-LPN instead of an LPN. This is useful for work assignments that contain case or each picks being sent to the same customer. For example, during distribution operations, an operator may pick work assignments for entire shipments that are for a single customer, such as a receiving distribution center. When work assignments are picked to sub-LPNs, the application retains and tracks the physical sub-LPNs throughout the distribution process, and also sends the information to the host. The host can then send an ASN with accurate sub-LPN information to the receiving warehouse.

When an operator starts a work assignment that is configured to be picked to a sub-LPN, the operator scans the physical sub-LPN as the To ID (the identifier for the container or pallet to which the work assignment is picked). The application automatically generates an LPN identifier to associate with the physical sub-LPN; therefore, each work assignment (and its picked inventory) is associated with a unique sub-LPN (user defined) and a unique LPN (application defined). The application also tracks the sub handling unit type for each sub-LPN, if applicable. However, if new containers are added while picking a single work assignment, then each new container has a unique sub-LPN (and application-generated LPN), different from the sub-LPN to which the work assignment was previously being picked. The same applies to each additional slot or tote (sub handling unit) that is picked to on a trolley during work assignment slot picking.

Picking a work assignment to a sub-LPN is supported for items that are configured to be received and tracked at any level: LPN (pallet), sub-LPN (case), and detail LPN (each). If the inventory is sub-LPN tracked, the individual case numbers (sub-LPNs) and other information (such as case serial numbers or case weight) is not retained by the application; the sub-LPN to which the work assignment is picked is used to track and identify the inventory. However, if the inventory is serialized at the detail (each) LPN level, then the application retains and tracks the serial numbers for the eaches, but still replaces the individual case numbers with the To ID sub-LPN that was scanned prior to starting the work assignment.

If picks for one or more work assignments (created using a rule configured to pick to a sub-LPN) are used for pallet building, then the application continues to track the sub-LPNs to which the work assignments were originally picked, as well as the newly built LPN. The application also tracks the sub-LPNs for any work assignment picks that are cross docked or deposited to a store location during distribution operations.

In the application, when you view inventory that was picked to a sub-LPN, the To ID sub-LPN for the work assignment is displayed as the top-level LPN in the inventory grid.

**Notes**:

-   Carton picks are excluded from work assignments built with a rule configured to pick to the sub-LPN level.
-   If the **Require Sub-LPN Capture** inventory settings configuration is set to Yes for the warehouse or client (in a 3PL environment), then the application tracks the case identifier and respective catch quantity. However, if a work assignment is picked to a sub-LPN, the individual case information (including catch quantity) is no longer retained. Therefore, the application does not prompt for sub-LPN capture if a work assignment is picked to a sub-LPN.
-   Voice devices do not support tracking handling units. Therefore, when a voice operator picks a work assignment to an LPN or sub-LPN, the application does not track any associated handling unit or sub handling unit type.
    

### Setup

You must perform the following tasks to pick work assignments to sub-LPNs:

1.  Configure a work assignment rule. Specify the criteria used to build work assignments from the rule, and set the **Pick to LPN Level** field to Sub-LPN (Case). See [Add or modify work assignment rules](work-assignments/procedures-for-work-assignments.md).
2.  If applicable, configure movement zones to support split transfers. When picking work assignments to slots, for the application to display the sub-LPN for each slot on a trolley during deposit, the movement zone to which the inventory is deposited must be configured with the **Split Transfers** field set to Yes. If set to No, the application displays the trolley LPN instead. See [Add or modify a movement zone](../../inventory/movement/movement-zones.md).

## Starter pallets

A starter pallet is a large quantity base pick that is used to begin a picking tour that may or may not result in a full pallet. It is typically the first pick in a pick tour, because it creates an LPN platform for subsequent picks. Picking a partial LPN instead of multiple cases typically saves time because it involves one pick instead of many case picks, and eliminates having to hand-stack smaller UOMs on a new platform. A starter pallet can be picked from either a pickface or a reserve storage location. Standard pick release rules determine the source of the pick.

The following considerations can help determine whether you want to use starter pallets:

-   Starter pallet pick assignment is determined by standard work manager functionality. The configuration and rules for location access, operator authorization, priority, and proximity are all enforced. In the event that a work assignment is split between operators (for example, due to location access), the operator is directed to deposit the pallet to a P&D location so that another operator can pick it up and resume the assignment.
-   If Warehouse Labor Management is integrated with Warehouse Management, starter pallet picks are reported to Warehouse Labor Management as a discrete event, not as a list of case picks. The action of obtaining a starter pallet is considered a unique pick start event.

The following types of starter pallets can be allocated:

-   **Full Pallet Starter**: Used when the pick quantity allows for an entire pallet to be picked from a location. This occurs when a partial pallet quantity matches or is less than the ordered quantity, or when a full pallet of an item is defined to be less than the targeted capacity defined for the work assignment. This type of starter pallet does not require a threshold pick for it to be generated.
-   **Threshold Picking Starter**: Used when the operator is directed to pick a pallet UOM in order to satisfy an order quantity that is slightly less than the pallet UOM. The unneeded inventory is removed from the pallet and deposited to an appropriate location. For more information, see [Threshold picking](threshold-picking.md).

## Starter pallet setup

You must perform the following tasks to configure the application to allocate starter pallets for a work assignment:

**Note**: A starter pallet is a large-quantity base pick that is used to begin a picking tour that may or may not result in a full pallet. It is typically the first pick in a pick tour, because it creates an LPN platform for subsequent picks. Picking a partial LPN instead of multiple cases typically saves time because it involves one pick instead of many case picks, and eliminates having to hand-stack smaller UOMs on a new platform.

1.  Define the following starter pallet attributes in the work assignments configuration:
    -   Pick zones from which starter pallets can be allocated.
    -   Sequence in which pallets are selected to be used as a starter pallet, such as by pallets with the most quantity (potentially full pallet UOMs) to pallets with the least quantity. If this sequence is not resulting in the cleanup of partial pallets in a reasonable manner, then you may need to adjust the order-by value to be from least quantity to most quantity.
    -   Maximum number of starter pallets that can be included in a single work assignment for the transport equipment handling unit type. This value is used if there is no transport equipment associated with the shipment or if there is no maximum value associated with the transport equipment handling unit type. The maximum number of starter pallets is typically configured to correspond to the number of floor spots on the transport equipment. You can set this value to zero or blank if you do not want to limit the number of starter pallets on a work assignment.
    -   Whether full pallets can be used as starter pallets. If you allow full pallet picks as starter pallets and you set the sequence to be from most quantity to least quantity, you may need to change the sequence if this configuration results in the allocation of all or most of the starter pallets from full pallet quantities.
2.  Configure a work assignment rule. A work assignment rule is a configuration that specifies the criteria used to find and arrange picks in a work assignment that can be generated, released, and then performed by a picking operator. When you define a work assignment rule, you can specify the maximum number of starter pallets allowed in the work assignment. The value for the **Maximum Number of Starter Pallets** on a work assignment rule overrides the value the value set for the **Maximum When Not Specified** field on the work assignment.
