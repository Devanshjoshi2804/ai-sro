Movement Zones

In this topic
  • Movement Zones
    • Movement zone replenishment attributes
    • Zone consolidation
    • Add or modify a movement zone
    • Delete a movement zone
    • Consolidate zones
    • Movement Zones fields

A movement zone represents a group of locations that have the same attributes (such as for splitting LPNs, replenishments, and inventory consolidation) for moving inventory. Any location to or from which inventory is moved using directed work must belong to a movement zone; therefore, most locations in the warehouse will belong to a movement zone.

For example, storage locations to which inventory can be deposited and processing locations to which inventory can be moved for packing are the types of locations that must be assigned to a movement zone for the application to select those locations for putaway or deposit. Another example is pickup and deposit (P&D) locations situated at the end of an aisle where inventory is temporarily deposited prior to putaway.

Each source, hop (intermediate stop), and destination location that you want to include in a movement path must be assigned to a movement zone so that inventory transfers and moves can take place from one zone to the next. For example, for an operator to be directed to deposit picked inventory to a wrapper location prior to ship staging, a movement zone must be defined for the picking locations, wrapper locations, and staging locations. The picking movement zone is the source, the wrapper movement zone is the hop, and the staging movement zone is the destination.

To accomplish the move, the application evaluates the locations assigned to the wrapper movement zone and directs the operator to the optimal location in the wrapper zone to deposit the inventory. After being wrapped, the inventory is directed to an appropriate staging location.

When you define a movement zone, you specify the following attributes:

  • General attributes that define how the application manages inventory moves into and out of locations in the zone.
  • Directed work that is generated automatically when inventory is deposited to the movement zone. This is an optional configuration that automates the next move; otherwise, operators use manual moves to take inventory to its next location in the path.
  • Graphic display of the movement zone drawn on the warehouse or building map.

Movement zone replenishment attributes

When you configure replenishment attributes for a movement zone, you define whether the application attempts to fill the pickfaces for an item during an emergency or demand replenishment. For example, if a pickface that has a capacity of 2,000 units has 200 remaining and an order needs 500 units, the application creates an emergency replenishment for 300 units to fill the order. However, if one LPN contains 1,000 units, instead of creating an emergency replenishment for 300, the application moves the entire load to the pickface during the replenishment. Once the order is filled with the 200 units originally in the location and 300 units from the replenishment, the pickface now contains 700 units.

Note: The application attempts to move additional inventory to a pickface in the highest quantity possible without creating a move to the pickface in addition to the moves required by the emergency or demand replenishment.

In addition, if Slotting is installed and enabled in Warehouse Management, you can configure the following attributes for a movement zone:

Note: Slotting is only used to slot pickface locations.

  • The default inventory status for manual and dynamically generated (as a result of Slotting integration) replenishment item configurations. This is the default inventory status required for inventory used to replenish locations in the zone.
  • The default method for calculating replenishment points for dynamically created replenishment item configurations for the movement zone. The replenishment points can be calculated by either a percentage of a location's capacity or a unit quantity. You define values for the following points:
    • Minimum: If a location falls below the minimum value (percentage or unit quantity) when executing a slotting plan, then Warehouse Management automatically replenishes the location.
    • Maximum: Represents the maximum value (percentage or unit quantity) to which you want Warehouse Management to fill a location during an automatic replenishment resulting from the execution a slotting plan.

Zone consolidation

You can use the Consolidate action, available from any zone configuration grid, to consolidate zones that share a common configuration into a single (original) zone. You can consolidate the following types of zones: count zones, movement zones, pick zones, storage zones, and work zones. See Consolidate zones.

When you select a zone and use the Consolidate action, the application presents a list of zones that have a configuration that matches the selected (original) zone. You can then select one or more of the matching zones to consolidate to the original zone.

During consolidation, the application performs the following tasks:

  • Updates all the configurations and references for the zones that are being consolidated to now use the original zone. For example, if PickZone2 and PickZone3 are consolidated into PickZone1, then the locations assigned to PickZone2 and PickZone3 are reassigned to PickZone1.
  • Removes the consolidated zones and retains the original zone.
  • Displays a progress bar that shows the processing status of the consolidation.
  • When consolidation is complete, displays the list of any remaining consolidation candidates that match the original zone. This allows you to continue consolidating to the original zone.

The same process is available for location types using the location type configuration. See Location type consolidation.

Add or modify a movement zone

  1. Select Configuration > Inventory > Movement > Movement Zones.
  2. Perform one of the following tasks:
    • To add a movement zone, from the Actions drop-down list, select Add.
    • To modify a movement zone, in the grid, click the movement zone.
    • To copy a movement zone, in the grid, select the check box next to the movement zone, and then from the Actions drop-down list, select Copy.
  3. Enter information in the Movement Zones fields.
  4. Click DIRECTED MOVES or Next.
  5. To enable the application to generate directed work to move inventory out the zone after the inventory has been deposited to the zone:
    1. Perform one of the following tasks:
      • To add a directed move, click Add.
      • To modify a directed move, in the grid, click the destination zone.

    2. Enter information in the following fields:

      FieldDescription
      Destination Zone

      The movement zone to which inventory should be moved next.

      Operation Code

      Operation for the directed work that is generated to move inventory to the destination zone.

      Priority

      Priority at which the directed work is placed into the work queue initially to accomplish the work. If you do not provide a value for Priority, then the work enters the work queue at the base priority defined for the operation.

    3. Click Apply.
  6. Click LAYOUT or Next.
  7. To draw the zone on the warehouse map for the selected building:
    1. Click View, and then select the check box for each option that you want to display on the map.
    2. Click Draw, and then move and size the shape on the page.

  8. Click Finish.

    Note: To assign locations to a movement zone, see the information on modifying multiple locations in Location configuration process.

Delete a movement zone

You cannot delete a movement zone if a location is assigned to it.

  1. Select Configuration > Inventory > Movement > Movement Zones.
  2. In the grid, select the check box next to the movement zone to delete.
  3. From the Actions drop-down list, select Delete. A confirmation message is displayed.
  4. Click OK.

Consolidate zones

You use the following procedure to consolidate zones that have the same configurations into a single (original) zone. See Zone consolidation.

Note: Zones cannot be consolidated if outstanding work references the selected zone.

  1. Perform one of the following tasks:
    • For count zones, select Configuration > Inventory > Counting > Count Zones.
    • For movement zones, select Configuration > Inventory > Movement > Movement Zones.
    • For pick zones, select Configuration > Outbound > Allocation > Pick Zones.
    • For storage zones, select Configuration > Inbound > Storage > Storage Zones.
    • For work zones, select Configuration > Work > Work > Work Zones.
  2. In the grid, select the zone to which duplicate zones will be consolidated. This becomes the original zone that remains after the duplicate zones have been removed. This is also the zone to which references and configurations are reassigned.
  3. From the Actions drop-down list, select Consolidate. A list of zones that have the same configuration as the original zone are displayed.
  4. In the grid, select the check box next to the zones to consolidate. The selected zones will be removed after consolidation takes place.
  5. Click Save. The selected zones are removed, and the Consolidation page displays the remaining zones, if any, that match the original zone.

Movement Zones fields

Field Description
Zone Name

Name for a group of locations that share the same attributes for moving inventory.
Building

Building in which the movement zone is located. A building is a warehouse entity consisting of one or more zones. Inventory and location information can be reported by building.
Description

Text that further describes the zone.
Split Transfers

If Yes, the movement zone supports the splitting of LPNs during an LPN transfer. When an LPN is moved out of the movement zone, if its details (sub-LPNs or detail LPNs) have different next locations on the movement path, the application prompts the user to split the LPN and the application updates the picking information for all of the sub-LPNs and detail LPNs on the LPN.

If your warehouse is configured for picking to handling unit slots, then the sub handling unit (such as a tote) must be deposited individually off of the master handling unit (such as a trolley). For example, when an operator is in a location that is located in a movement zone configured for LPN splitting and the operator deposits a master handling unit LPN, the operator is prompted to scan or create an LPN for each slot deposit. When the sub handling unit in the slot is deposited, it is no longer associated with the master handling unit.

If No, the zone does not support LPN splitting during an LPN transfer. If your warehouse is configured for picking to handling unit slots, then slots remain on the master handling unit during deposit.
Scan New LPNs

If Yes, then when an operator splits a quantity off of an LPN during an inventory transfer or cross docking, the operator can enter a new LPN for the quantity (for example, from a roll of pre-printed labels).

If No, then when an operator splits an LPN, the application generates a new LPN for the quantity that was split off from the original LPN.
Destination Locations

If Yes, the application clears the assignment of a destination location from an LPN if the LPN is staged before being put away. When a destination location is allocated for putaway, the application reserves the location for the quantity of inventory pending to the location. By clearing the destination location, the pending quantity is removed, and the reserved space in the location can be used for other inventory. When the operator resumes putaway of the LPN, the application re-allocates a destination location for the inventory.

If No, the application does not clear the assignment of a destination location from an LPN when the LPN is staged before being put away. When putaway is resumed, the operator is directed to the location that was originally reserved.

Recalculate Putaway Location

If Yes, the application should recalculate and find the most appropriate putaway location, including cross dock opportunities, when inventory is picked up from locations in the area. This is done to ensure that the most current data is used in determining a putaway location.

If No, the application does not recalculate the best putaway location.

Fill to Capacity

If Yes, then the application will attempt to fill a location during an emergency or demand replenishment. When a replenishment is generated to fill an order, the application also attempts to move additional product to fill the pickface. The application only attempts to move additional product so as not to create an additional move to the pickface or to surpass the capacity of the location.

For example, if a pickface that has a capacity of 2,000 units has 200 remaining and an order needs 500 units, the application creates an emergency replenishment for 300 units to fill the order. However, if one load contains 1,000 units, instead of creating an emergency replenishment for 300, the application directs the entire load to the pickface during the replenishment. Once the order is filled with the 200 units originally in the location and 300 units from the replenishment, 700 units remain the pickface.

Note: The application attempts to move additional inventory to a pickface in the highest quantity possible without creating a move to the pickface in addition to the moves required by the emergency or demand replenishment.

If No, the application will not attempt to fill the location when generating an emergency or demand replenishment.

Allow Dynamic Pick Face Triggered Replenishments

If Yes, then when an item is stored in a dynamic pickface location in this zone and the inventory level reaches the defined replenishment minimum, the application attempts to create a triggered replenishment. An item is stored dynamically if the item's replenishment configuration specifies a movement zone but not a specific location. When the item is stored in the zone, the application dynamically selects a storage location not already associated with an item. Select Yes if you want to continue using the application-selected location for items that are stored dynamically.

Note: If you select Yes and want to clear the dynamic location of inventory, you must either cancel the replenishment or move the inventory to a different location.

If No, then when an item is stored in a dynamic pickface location in this zone and the inventory level reaches the defined replenishment minimum, a triggered replenishment is not created. Select No if you do not want locations in the zone to be refilled with the item was dynamically assigned to the location during a previous replenishment process.

Note: This configuration only affects triggered replenishments. If additional inventory for an item in a dynamic location is needed for an order, the application can still generate an emergency replenishment to the location.

Ignore Mixing Restrictions on Release

If Yes, then the application does not validate mixing restrictions when a demand replenishment is released. If you select Yes, then the application validates mixing restrictions for demand replenishments to locations in the zone when the replenishment work is unlocked. If a zone is configured for pre-inventory allocation (PIA) and if demand replenishments are configured to be created in a Locked status, it is possible for multiple demand replenishments to be created for a single location. With this field set to Yes, the application can release a demand replenishment in a Locked status to a location even if the location contains inventory that cannot be mixed with the replenishment inventory at the time of allocation. When a locked replenishment no longer violates the mixing restrictions and the location has available capacity, the application unlocks the work so that it can be performed.

Note: If the replenishment work is manually unlocked, the application does not validate the mixing restrictions.

Select Yes if you want to allow multiple PIA demand replenishments to be allocated for a location regardless of whether the mixing restrictions are satisfied at the time of allocation.

If No, then the application validates the mixing restrictions when the replenishment inventory is allocated.

Allow Overpicking Replenishments

If Yes, an operator can override the application and pick a quantity greater than the application-directed value during replenishment to a location in this zone. For example, if the current quantity on hand in the destination location is completely allocated, the operator can choose to overpick during replenishment knowing that picking will deplete the quantity in the destination location. Because overpicking during replenishment could overfill a location, you may not want to enable this feature where it is not physically possible to overfill a location, such as in a narrow aisle.

If No, the operator is not allowed to override the application-directed value.

Cancel Associated Picks or Shorts

If Yes, the application cancels the associated picks when an emergency or demand replenishment is cancelled, and cancels the associated replenishment, if necessary, when an order pick is cancelled. Specifically, if you select Yes, then the application cancels associated picks and replenishments in the following ways:

  • When an order pick cannot be fulfilled, the short allocation results in an emergency replenishment. If the replenishment pick is cancelled, then the associated short allocation (unfulfilled order pick) is also cancelled, or cancelled and reallocated, depending on the cancel code. If the unfulfilled order pick is cancelled instead, the emergency replenishment is only cancelled if no other short allocations or orders require the inventory.
  • When pre-inventory allocation (PIA) is used and a PIA pick cannot be fulfilled, the application creates a demand replenishment. If the demand replenishment is cancelled, then the associated PIA pick is also cancelled. If the PIA pick is cancelled instead, then the demand replenishment is only cancelled if no other outstanding picks require the inventory; the demand replenishment may also be regenerated if the PIA pick is cancelled with reallocation. If a PIA pick associated to a pending top-off, triggered, or manual replenishment is cancelled, then regardless of this configuration, the replenishment is not cancelled.

Note: If an emergency replenishment or demand replenishment pick is cancelled with reallocation, the replenishment pick is cancelled, but the original unfulfilled order pick is reprocessed by the application.

When an order pick or PIA pick is cancelled, the application considers this configuration for the source movement zone associated with the pick. When a demand or emergency replenishment is cancelled, the application considers this configuration for the destination movement zone.

Select Yes, for example, in a zone where dynamic pickfaces are used so that if an order is cancelled, the pending replenishment to fill the dynamic pickface is also cancelled (if no other outstanding picks require the inventory). If no other inventory exists in the location, this allows the application to reuse the location for other inventory.

If No, then the application does not cancel the associated order pick when a replenishment pick is cancelled, and does not cancel the associated replenishment when an order pick is cancelled.

Allocate Maximum UOM

If Yes, the application can allocate inventory out of the zone at a larger UOM that what is required for a replenishment pick. The allocated UOM is moved to an intermediate location (such as a pickup and deposit location) from which the replenishment pick can be performed. Following the pick, the remaining inventory must be returned to storage.

Select Yes, for example, if inventory required for replenishment resides in a location that is only accessible by full pallet material handling equipment. The application can allocate a full pallet from a location in the zone, move it to a pickup and deposit location, and then allocate replenishment picks at a lower UOM level, such as cases. After the case picks are performed, the pallet LPN with the remaining inventory must be returned to storage.

If No, then during replenishment processing, the application is not allowed to allocate inventory out of the zone at a larger UOM than what is required for a replenishment. For example, select No to prevent the application from allocating a pallet LPN from the zone to satisfy a case (sub-LPN) replenishment quantity.

IMPORTANT: If this zone is the source zone for replenishments to a destination movement zone configured with the Split Replenishment Residuals field is set to Yes, then the Allocate Maximum UOM must be set to No.

Split replenishment residuals

If Yes, then if a replenishment pick exceeds the quantity needed for the replenishment request, and the residual inventory does not fit in the destination location, then the residual inventory can be split and directed elsewhere. If configured to do so, residual inventory can be used to fulfill cross docks; otherwise, the application runs putaway to find a location.

Note: Additional configuration is required for this functionality. See Splitting replenishment residuals.

For example, assume that a pickface location has a capacity of 50 eaches, and that the location currently has a quantity of 10 eaches. If an order requires 30 eaches, then the application creates a replenishment to fulfill the order. If this field is set to Yes and the application allocates more than the destination location can hold, then at the replenishment location, the application prompts the operator to deposit 40 eaches to fill the location to capacity. After the operator completes the deposit, the application processes the residual inventory from the replenishment pick. If configured to do so, the residual inventory can be used to fulfill cross dock opportunities. If there are no cross docks or that functionality is disabled, then the application runs putaway to find a location for the residual inventory. If allowed, the operator can override the application-directed location.

Notes:

  • Splitting replenishment residuals can be used to avoid returning partial pallets to storage where they can no longer be allocated as a full pallet quantity.
  • If the Overfill field is set to Yes in the replenishment settings configuration, then when prompted with the deposit quantity that fills the replenishment location, the operator can override the quantity with a quantity that exceeds the location capacity.
  • If this field is set to Yes, then the Allocate Maximum UOM field on the source movement zone must be set to No.

If No, then replenishments cannot be split.

Display Case Equivalent on Replenishment Split

If Yes, then when splitting replenishment residuals is enabled and a replenishment is split, the application displays the deposit quantity to the replenishment location in the item’s case-equivalent UOM. For example, If the location can hold 40.5 cases (45 eaches), then with this field set to Yes, the application displays a deposit quantity of 40 cases. The remaining 5 eaches that would fill the replenishment location are instead included in the residual quantity for splitting. Select Yes to ensure that replenishment deposits to locations in this zone are always completed in quantities of the case-equivalent UOM. If at least 1 case-equivalent UOM will not fit in the location, then the application displays the next smallest UOM that can fit in the location.

If No, then the application displays the deposit quantity UOM based on the location’s capacity and what is needed to fill the location. For example, if the replenishment location can hold 40.5 cases, then with this field set to No, the system displays a deposit quantity of 45 eaches to fill the location. With this field set to No, operators may be required to deposit partial cases (case-equivalent UOM) to reach location capacity.

Default Replen Config Inventory Status

If Slotting is installed and enabled in Warehouse Management, this is the default inventory status to use when creating replenishment item configurations. This value is displayed as the default inventory status when you manually create replenishment item configurations for this movement zone. This is also the inventory status that application uses when dynamically creating replenishment item configurations during the slotting plan execution.

Default Replen Configuration Level

If Slotting is installed and enabled in Warehouse Management, this value indicates how the application determines quantity when creating replenishment item configurations for this movement zone.

  • Percentage: Percentage of a location's maximum capacity (defined for a location).
  • Units: Number of units per location.

See Movement zone replenishment attributes.

Default Replen Minimum

Minimum value (percentage or unit quantity) representing the point at which a location should be replenished (refilled). If the amount in a location falls below the minimum value when executing a slotting plan, Warehouse Management automatically generates a replenishment to fill the location.

Default Replen Maximum

Maximum value (percentage or unit quantity) representing the amount to which a location should be filled during an automatic replenishment resulting from the execution of a slotting plan.

Attachment Strategy

Method by which the application handles the deposit of a partial LPN to locations in the movement zone. A partial LPN is a sub-LPN (such as a case) or a detail LPN (such as an each or piece). The attachment strategy determines whether the application attaches a partial LPN of inventory to an existing LPN when a partial LPN is deposited to a location in the movement zone, and if so, how the attachment takes place.

The attachment strategy only applies to the deposit of sub-LPNs and detail LPNs; full LPNs are not attached to other LPNs based on the attachment strategy. If you want all inventory to be on one LPN in a location, you must enable the attach to any strategy before the location contains any inventory.

Note: The Attachment Strategy field on a movement zone and the Automatic LPN Consolidation field on a storage zone are mutually exclusive. To avoid unexpected behavior, if a location belongs to a movement zone with this field set to attach (any value besides Never Attach), then the location's storage zone must be configured with the Automatic LPN Consolidation field set to No.

  • Never Attach: When a partial LPN of inventory is moved to a location, a new LPN is created on which to attach or deposit the inventory.
  • Attach To Any: When a partial LPN of inventory is moved to a location that already contains inventory, the application attaches the inventory to any existing LPN in the location. If a location does not contain inventory, the application creates a new LPN number for the partial LPN. This strategy is typically used in movement zones that allow only case or each picking, where all the inventory resides on a single LPN.
  • Attach If Exists: When a partial LPN of inventory is moved to a location that already contains inventory, the application attaches the inventory to any existing LPN in the location. If a location does not contain inventory, the operator is not allowed to deposit a partial LPN in the location.
  • Attach If Unique: When a partial LPN of inventory is moved to a location that already contains inventory, an operator is required to identify the LPN on which the partial LPN is deposited. If a location does not contain inventory, the application creates a new LPN number for the partial LPN. This strategy is typically used in movement zones that allow LPN (pallet) picking.

Quantity Verification Only

If Yes, then in locations where inventory is stored in cases (sub-LPNs), the operator is allowed to directly perform each picks from and inventory counts on cases in the location without entering the inventory identifier (sub-LPN) of the source case. Instead, the operator enters a quantity. Set this field to Yes when you do not need to track the carton contents in the source location from which the operator performs counts and each (piece) picks. This field only applies to locations in which inventory is stored in cases and, for picking, only applies to each picks that are sourced from cases (sub-LPNs).

Note: If this field is set to Yes and multiple sub-LPNs are deposited to a location in this zone, then the application consolidates the sub-LPNs onto a single sub-LPN. If there is inventory in the location, the deposited sub-LPNs are consolidated with the existing sub-LPN. However, the application does not consolidate sub-LPNs with serialized inventory.

If No, then when picking or counting at locations used to store sub-LPNs, the operator is required to enter an inventory identifier (sub-LPN) to confirm the case that is counted or from which a quantity is picked.

Audit

If Yes, operators performing distribution deposit are required to perform an audit upon completing the deposit process for a distribution. During the audit, the operator is required to enter whether there is residual inventory on the LPN after the deposit work is completed. If there is residual inventory, the operator enters the quantity and the application compares the entered residual quantity against the expected residual quantity. If the quantities match, the audit passes and the operator is directed to place the residual inventory in a storage location determined by putaway. If the residual inventory does not match the quantity expected by the application, the audit fails and the inventory is directed to an exception location where it can be determined what caused the discrepancy in the residual inventory.

If No, operators are not required to perform a distribution audit upon completing the deposit process for a distribution. You would typically select No only in situations where all of the picked inventory is expected to be distributed, such as when eaches are picked for e-commerce orders and distributed to cartons for shipment.

RF Display Warning

If Yes, then an RF message is displayed when the application cannot reserve a location in the next zone of a movement path for the entire quantity being moved. This functionality is used when the application is configured to delay reserving the next deposit location in a movement path until the operator picks up the inventory from its current location.

For example, assume an operator picks up two LPNs from their current location to move them to the next zone in the movement path. If there are no locations available, the application presents a pickup and deposit (P&D) location in which all the inventory can be deposited. If a location in the next movement zone is available for depositing a partial quantity, the message indicates that locations are not available for all inventory and prompts the operator to either deposit the partial inventory to the intended zone (the remaining inventory is directed to an application-suggested P&D location), or deposit the entire quantity to the P&D location. For partial deposits, the application identifies the specific LPNs to be deposited to each location. You might select Yes if you want to give operators control over whether a partial deposit is made, and in some cases, to bypass a partial deposit so that the entire deposit to the next location can be made at one time.

If No, then an RF message is not displayed. If you select No and the application cannot find any locations, the operator is directed to deposit the inventory to an application-suggested P&D location. If a location is available for a portion of the inventory, then the operator is directed to deposit a partial quantity to the location in the next movement zone and the remaining inventory to a P&D location. For partial deposits, the application identifies the specific LPNs to be deposited to each location. You might select No if it is common for processing locations to be mostly full (eliminating the extra step of operators responding to the prompt), and if you always want to deposit as much inventory as possible to the next hop location.

Inventory Close

If Yes, the application automatically closes a shipping container when the last pick for the shipment is deposited in the container by an operator performing distribution deposit. Distribution deposit is the process of depositing picked inventory to a consolidation location in order to fulfill a distribution shipment. For example, if a distribution is for three items (requiring three picks) and the operator already deposited two picks into a shipping container, then when the operator deposits the third pick, the application automatically closes the container. Depending on the Automatic Pickup configuration for the location type, closed containers are either moved automatically to the operator's RF device or the application creates directed work for another operator to move the inventory to its next location. If there are multiple containers for the shipment, then all of the containers are closed and ready to be moved to their next location when the last pick is deposited to the final shipping container.

Note: If you select Yes, then you must also configure the application to reserve locations in the distribution deposit movement zone by shipment. See Processing Location Reservation.

If No, then the operator must manually close the containers for a shipment during distribution deposit.

Distribution Exception Location

Location to which the operator is directed to deposit unexpected residual inventory. After the operator completes the deposit work for an LPN at the required distribution locations, the operator is directed to perform an audit to determine if there is any residual inventory. During the application-generated audit, the operator enters the quantity of residual inventory, if any. The application compares the residual quantity against the expected residual quantity. If the quantities match, the audit passes and the operator is directed to place the residual inventory in a storage location determined by putaway. If the quantities do not match, the audit fails and the inventory is directed to the distribution exception location where the cause of the discrepancy can be determined.

Allow Pallet Build

If Yes, pallet building is allowed in the movement zone. Pallet building is a process in which cases or cartons are consolidated to create a new pallet.

If No, pallet building is not allowed in the movement zone.

Pre-Stage

If Yes, indicates that this movement zone is used for pre-staging before the final staging location.

A pre-stage movement zone is used in the outbound work sequencing process to provide buffer hop locations in the movement path to which picked inventory can be deposited. If a pre-stage movement zone is defined in the movement path, then pick work that would otherwise be locked at source locations (and only unlocked based on outbound work sequence) would be unlocked immediately for picking to pre-stage locations. This is done so that pick work in the work queue for smaller UOMs (which typically have a longer lead time) can be unlocked for picking but not for staging. At the pre-stage location, transfer work to staging for the picked inventory is locked in the work queue until the work sequencing process unlocks it.

For example, assume that outbound work sequencing is enabled, the work release sequencing type on the outbound load is by stop, and movement paths for case pick and each pick locations among other hops (like Print/Wrapper stations) include a pre-stage movement zone. Assume also that movement paths for pallet picks have other hops (like Print/Wrapper stations) but not a pre-staging hop. During allocation, pick work for the load is created in the work queue. Case pick or Each pick work having a pre-stage movement zone defined as a hop in the movement path are not locked (ignoring any outbound work sequence). However, subsequent work out of the pre-staging hop to the staging destination is locked. Pallet pick work is locked at source zones and will be unlocked along with any locked transfers out of pre-stage by outbound work sequence only after all the cases and eaches are pre staged. When the first stop is completely staged, then pick and transfer work for stop 2 is unlocked for delivery to staging; and so on.

Note: If a movement path contains pre-stage zones, the application does not override the initial status of work created for an operation. For example, if an operation is configured to be created with an initial status of Locked and pre-staging is used, the work to pick inventory to the pre-stage zone remains in a locked status until manually unlocked. Therefore, to ensure that work is available for operators to complete prior to pre-staging, the Initial Creation Status field for the operation should be set to Pending. This field is only available if outbound work sequencing is enabled. See Outbound work sequencing.

If No, then this movement zone is not used for pre-staging.
