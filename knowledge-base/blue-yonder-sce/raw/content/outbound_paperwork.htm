Outbound Paperwork

In this topic
  • Outbound Paperwork
    • Delivery note numbers
    • Configure outbound paperwork
    • Outbound Paperwork fields
    • Delivery Note Number fields

Shipping paperwork provides the carrier with a contract and receipt for the goods that it agrees to transport and deliver. You specify the levels at which paperwork should be printed and whether printing is required before the transport equipment for the shipment is closed. You can also specify when an operator is prompted for a document number and whether or not a document number is required to be assigned prior to printing the paperwork. Paperwork is generally printed once shipments are at or beyond the staged process.

You also can specify the default level at which a bill of lading (BOL) is provided when a master BOL is required.

Delivery note numbers

A delivery note number is a shipment identifier that is typically used in geographical regions where it is a legal requirement. The delivery note number used by a client or a warehouse can contain numbers, letters, and special characters, and needs to be unique throughout the year.

You can configure a prefix and a suffix for the generated number, as well as define the sequence range; each new delivery note number created has its sequence value increased by a value of 1. When a shipment's status is changed to Staged, the application generates the delivery note number based on the configuration and assigns it to the shipment. For example, if you configured the prefix as A, the suffix as B, and the sequence range 0-999, then the first number generated by the application would be A000B, followed by A001B, then A002B, and so on.

When the sequence range has been completed, which should typically happen once a year, you can reset the sequence so that it is reused to create unique delivery note numbers specific to a new year. If a delivery note number for a shipment exceeds the maximum value in the sequence range, a number cannot be generated and the shipment's status cannot be changed to Staged; the sequence must be reset or the maximum sequence value must be increased.

Note: Resetting the delivery note number sequence cannot be reversed.

Configure outbound paperwork

  1. Select Configuration > Outbound > Shipping> Outbound Paperwork.
  2. Enter information in the Outbound Paperwork fields.
  3. To select the default level at which a bill of lading (BOL) should be printed for a transport mode:
    1. Under BOL LEVEL, click Add BOL Level.
    2. In the grid, click a transport mode.

    3. In Bill Of Lading Break Level column, from the drop-down list, select the level.

      Note: If you leave the Bill Of Lading Break Level blank, a BOL will not be printed.

    4. Click Apply.

  4. To configure shipment status change notifications for a 3PL environment:

    Note: Clients typically are configured to receive these notifications so they can relay the status of a shipment to the end customer that placed the order.

    1. Under SHIPMENT STATUS CHANGE NOTIFICATIONS, click Add Shipment Status Change Electronic Delivery to Host.
    2. In the Available column, select the check box next to the client and shipment status combinations for which the application will send a notification to the client's host system. For example, if for CLIENT A you select the Loaded status, then whenever a shipment for that client transitions to Loaded, the application sends a transaction to the host.
    3. Click Apply.
  5. To configure a delivery note number sequence for shipments, under DELIVERY NOTE NUMBER, click Delivery Note Number Format and perform one of the following tasks:
    • To configure a delivery note number for a warehouse not operating in a 3PL environment:
      1. Enter information in the Delivery Note Number fields.
      2. Click Save. A confirmation message is displayed.
      3. Click OK.
      4. To delete the delivery note number configuration:
        1. Click Delete. A confirmation message is displayed.
        2. Click OK.

      5. To reset the delivery note number sequence for the warehouse:

        Note: Resetting the delivery note number sequence causes the application to generate numbers beginning with the Starting Sequence value. Resetting the sequence cannot be reversed. You typically reset the sequence once a year when the old sequence has been completed.

        1. Click Reset Sequence. A confirmation message is displayed.
        2. Click Yes.
      6. Click .
    • To configure a delivery note number for a client in a 3PL environment:
      1. Perform one of the following tasks:
        • To add a new client configuration, click Add.
        • To modify a client configuration, in the grid, click the client.
      2. Enter information in the Delivery Note Number fields.
      3. Click Save.
      4. To delete a delivery note configuration for a client:
        1. In the grid, select the check box next to the client.
        2. Click Delete. A confirmation message is displayed.
        3. Click OK.

      5. To reset the delivery note sequence for a client:

        Note: Resetting the delivery note number sequence causes the application to generate numbers beginning with the Starting Sequence value. Resetting the sequence cannot be reversed. You typically reset the sequence once a year when the old sequence has been completed.

        1. In the grid, select the check box next to the client.
        2. Click Reset Sequence. A confirmation message is displayed.
        3. Click Yes.
      6. Click .
  6. Click Save.

Outbound Paperwork fields

Field Description
When to Prompt

Determines when the operator is prompted to print shipping paperwork.

  • Load: The operator will be prompted to print paperwork for every load.
  • Stop: The operator will be prompted to print paperwork for every stop.
  • Shipment: The operator will be prompted to print paperwork for every shipment.
Prevent Transport Equipment Close

If Yes, an operator cannot close a piece of transport equipment until paperwork has been printed for all of its shipments. Shipping paperwork serves as a legal record of what the transport equipment contains. Select this option if you want to ensure that paperwork is printed, if it is not the operator's responsibility to print it, or if transport equipment is configured to be closed automatically.

If No, an operator can close transport equipment regardless of whether paperwork has been printed for its shipments. Select this option if your facility waits to print paperwork until the transport equipment is ready to depart. For example, if trailers are loaded, closed, and moved to the yard to await carrier pick up, then you would allow transport equipment to be closed without printing paperwork.
Prompting

If Yes, the operator is prompted to enter document numbers during transport equipment loading. If your facility uses pre-printed bills of lading or other shipping paperwork, you may want to select Yes so that you can associate the document number with the load in the application.

If No, the operator is not prompted to enter document numbers during loading.
Required

If Yes, a document number must be assigned before shipping paperwork will be printed at the level indicated. A document number is an identifier for shipping paperwork related to all of the shipments assigned to an outbound load. You may want to select Yes if the document number is supplied from outside of the application, such as distributed by a carrier, to ensure it is displayed on the shipping paperwork.

If No, an operator is not required to assigned a document number before the shipping paperwork will be printed.
Delivery Note Numbers Required

If Yes, then the application attempts to generate and assign a delivery note number to each outbound shipment that reaches a Staged status. The delivery note number is based on the delivery note number format defined for the warehouse or, for a 3PL environment, the client. A delivery note number is a shipment identifier that is typically used in geographical regions where it is a legal requirement.

If No, then delivery note numbers are not assigned to outbound shipments.

Delivery Note Number fields

Field Description
Client

Unique identifier for a client who houses inventory within a multi-client (third-party logistics) warehouse. The client identifier distinguishes one client from another so that the application can effectively manage inventory and activities for multiple clients in the same warehouse.
Prefix for Delivery Note Number

Value that is used as the prefix for the application-generated delivery note number assigned to a shipment. The prefix can contain letters, numbers, and special characters, and has a limit of ten characters. For example, if the prefix is "ABC_", then all the delivery note numbers generated using this configuration will be in the following format: ABC_001SUF, where 001 is the variable sequence value and SUF is the defined suffix. A prefix is not required to generate a delivery note number.
Starting Sequence

Starting sequence value for a delivery note number generated using this configuration. When the sequence begins or is reset, this is the value that is used in the first delivery note number generated. Each subsequent number increases by a value of 1 until the ending sequence number is used. For example, assume that A is the prefix and B is the suffix; if the starting sequence is 0 and the ending sequence is 999, then the first delivery note number generated by the application would be A000B, followed by A001B, then A002B, and so on.

When you define the starting and ending sequence values, it is recommended that you take into consideration an estimate of the number of shipments your facility processes in a year either collectively or, in a third-party logistics (3PL) environment, for a specific client. A smaller sequence range may result in having to reset the sequence sooner than expected, meaning that duplicate delivery note numbers may be generated if the originals have not been purged from the application.

The maximum range is a starting sequence of 0000000000 and an ending sequence of ZZZZZZZZZZ.
Suffix for Delivery Note Number

Value that is used as the suffix for the application-generated delivery note number assigned to a shipment. The suffix can contain letters, numbers, and special characters, and has a limit of ten characters. For example, if the suffix is "-XYZ", then all of the delivery note numbers generated using this configuration will be in the following format: PRE001-XYZ, where PRE is the defined prefix and 001 is the variable sequence value. A suffix is not required to generate a delivery note number.
Ending Sequence

Ending sequence value for a delivery note number generated using this configuration. When delivery note numbers are generated, the application begins at the starting sequence value. Each subsequent number increases by a value of 1 until the ending sequence value is used. If this value is reached, the application can no longer generate delivery note numbers, and shipments that need a number cannot be staged unless the ending sequence value is increased or the sequence is reset.

For example, assume that A is the prefix and B is the suffix; if the starting sequence is 0 and the ending sequence is 999, then the first delivery note number generated by the application would be A000B, followed by A001B, then A002B, and so on until the last number in the sequence is used (A999B).

When you define the starting and ending sequence values, it is recommended that you take into consideration an estimate of the number of shipments your facility processes in a year either collectively or, in a third-party logistics (3PL) environment, for a specific client. A smaller sequence range may result in having to reset the sequence sooner than expected, meaning that duplicate delivery note numbers may be generated if the originals have not been purged from the application.

The maximum range is a starting sequence of 0000000000 and an ending sequence of ZZZZZZZZZZ.
