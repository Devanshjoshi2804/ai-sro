# Audit wave 1: root-cause fixes

Spec: `docs/audits/2026-09-23-codebase-audit.md` (findings C1, C2, C5, C6, C7, C8, C10 and §5 dead code). Direction: `docs/superpowers/specs/2026-09-23-vm-execution-recipes-and-agents.md`.

Out of this wave, by decision: C3/C4 (device credentials and roles; needs the owner to define admin vs operator), removing the old skill engine (execute_skill, intent resolve, threads pursue), and dropping any database table or column. Those come later.

## Global Constraints

1. **Root cause only.** Fix where the bad value or state is produced, once, for every caller. No hardcoded host, page text, job name, tenant or incident-specific branch. Code that learns from failures and improves itself is fine.
2. **Backend source carries no comments or docstrings.** Exceptions: docstrings under `backend/src/sro/interface/http/`, docstrings on classes listed in `frontend/openapi.json` schemas or pydantic models, and tool directives (`# noqa`, `# type: ignore[...]`, `# pragma`, `# fmt:`). Any explanation goes to `docs/code-notes/<source path>.md` under a heading `## \`<qualname>\`, line <N>: <Kind>` with the text quoted. Update or remove notes for code you change or delete.
3. **Architecture:** dependencies point inward (`interface → application → domain`, infrastructure only via `container.py`). `uv run lint-imports` must keep 4 contracts. No new port unless there is a new effect.
4. **Tests first for behaviour changes:** write the failing test, see it fail, then fix. Unit tests in `backend/tests/unit`; anything touching SQL gets an integration test in `backend/tests/integration` (Docker is available; testcontainers).
5. **Gates before each commit** (from `backend/`): `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy src tests` (exactly the 2 pre-existing errors in `tests/unit/application/test_converse.py` and `tests/unit/domain/chat/test_asking.py` are allowed), `uv run lint-imports`, `uv run pytest tests/unit -q`, plus the integration tests you touched. If a wire schema changes, run `make types` from the repo root and commit `frontend/openapi.json` and `frontend/src/lib/api/generated.ts`; `uv run pytest tests/contract -q` must pass.
6. **Schema changes:** additive Alembic migrations only (new nullable or defaulted columns). Never drop a table or column in this wave.
7. **Extension changes:** run the extension's tests (`cd new-chrome-extension && node --test src` or the Makefile's `test-extension` target) and `make lint-extension` if available.
8. **Git:** commit on the current branch only, with conventional messages ending in `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`. Never push, never merge, never switch branches, never touch untracked files outside your change, never delete files outside the task's scope.

## Task 1: Mining cost bugs (C6, C7)

- `application/observation/mine_lately.py` `_worth_a_pass`: `uow.gestures.tenants_since(...)` returns every tenant with new gestures, so any tenant's new work makes every tenant worth a pass. Replace it with a check scoped to this tenant (new gesture batches for THIS tenant since the last pass started). If the repository lacks a tenant-scoped query, add one to the port, the SQL repository and the fake.
- `application/observation/mining_pass.py` `fill_in_passwords`: the tenant's whole gesture store is read inside `for workflow in ...`. Read it once before the loop.
- In `mine()`, the spend cap (`over_cap`) must be checked before `fill_in_passwords` runs, so a capped tenant does no work at all. Keep the existing per-tenant lock semantics.
- Tests: tenant A's new gestures do not make tenant B worth a pass; `fill_in_passwords` reads gestures once regardless of the number of workflows (assert on the fake's call count); a tenant over the cap does not run `fill_in_passwords`.
- Fix the note in `docs/code-notes/.../mining_pass.py.md` that claims "reads a tenant's gestures once per pass" if it no longer matches, and any note the change invalidates.

## Task 2: An unreadable answer is not an answer (C5)

- `application/chat/reading_an_answer.py` `IsItAnAnswer.execute`: when there is no model, the call raises, or the reply has no data, it currently returns `answers=True` with the raw text. Return an explicit "could not tell" result instead (a third state, not `True`).
- `application/chat/converse.py` (the caller around the pending question): on "could not tell", do not take the text as the value and do not treat it as a new request. Ask the operator again, restating the question, and keep the pending question.
- The `spent` answer returned by `IsItAnAnswer` is currently discarded by converse. Record it the same way other chat readings are billed (a `ChatReading` row), so the spend cap sees it.
- `plainly_a_value` keeps its fast path unchanged.
- Tests: model raises → no value set, question asked again, pending kept; model returns no data → same; a clear answer still resumes; spend of a real reading is recorded.

## Task 3: Single-use passwords are bound to one run (C10)

- `application/execution/one_time_secrets.py` keeps plaintext passwords in a module-level dict keyed by tenant/system/field, expired entries are only removed on `take`, and any run in the tenant can take one.
- Bind each held secret to the run it was given for: the hold carries the `run_id`; `take` only releases it to that run. Sweep expired entries on every hold and take. Hold the store on the container (constructed once, injected) instead of module state.
- `POST /v1/secrets/once` must receive the run id. The panel's password box knows the run it is shown on (`new-chrome-extension/src/panel/run-card.js`, `api.js` `holdSecretOnce` or equivalent); send it. Validate that the run belongs to the tenant.
- Tests: a secret held for run A is not given to run B; an expired secret is gone after the sweep even if never taken; the route rejects a run id from another tenant; the extension sends the run id (extension test).

## Task 4: Sign-in is a fact about a job, not a guess at run time (C1, C2)

Current defects, both verified:
- `run_workflow.py` (after a failed send with `error_kind in K_NOT_HERE`): if `is_a_way_in(workflow, by_id)` and the browser is `elsewhere_is_ours` and not `signed_out`, the run is marked `held` and returns. `is_a_way_in` (`domain/skill/signing_in.py`) only checks that every cited gesture is on one origin, which most ordinary Blue Yonder jobs satisfy, so an ordinary job that loses its page is reported as succeeded with steps undone.
- `signs_in_at` picks "the only other job entirely on that origin" as the way back in, which can be any single-origin job.
- `may_write = (not leg.rescue) and (...)`: legs spliced in to sign back in bypass every write rule.

Required:
- Decide "this job signs in" once, from evidence, at mining time, and store it on the job (additive migration: a boolean on `workflows`, default false; set on new jobs by the mining pass and healed onto stored jobs by the existing healing pass). The rule must be general, not host-based: a job signs in when it types a secret (the recorder's secret mark) and does no business write (reuse the existing business-write test in `domain/skill/checks.py`, e.g. `_did_business`, or its equivalent). No IdP host lists or path fragments in this rule.
- Replace `is_a_way_in` in the run engine with that stored fact. Only a job tagged as signing in may end `held` because the browser has moved past its page. An ordinary job in that situation must not be reported held; it continues through the normal failure path.
- `signs_in_at` chooses among jobs tagged as signing in for that origin, never "any job entirely on the origin".
- Remove the `not leg.rescue` exemption from `may_write`. Spliced legs obey the same write rules as any leg. If this breaks the sign-in flow (e.g. a submit click on an identity page), fix the classification of that step, not by exempting legs.
- Tests: an ordinary single-origin job whose control is not found while the browser is elsewhere on our system is NOT held; a tagged sign-in job in the same situation is held; `signs_in_at` ignores untagged single-origin jobs; a spliced leg that writes is subject to `may_write`; the mining pass tags a secret-typing, non-business job and does not tag a job that types a secret and also writes business data. Integration test for the migration and repository round-trip.
- Update or delete `is_a_way_in` and its notes if nothing else uses it.

## Task 5: Every model call is metered (C8)

- Only `GeminiAsker` records cost. `GeminiInterpreter`, `GeminiIntentParser`, `GeminiVisionDriver`, `GeminiTranscriber` and `GeminiEmbedder` make unmetered calls; `from_the_mail` calls `understand` without writing a `ChatReading` or checking `over_cap`; `mail_job`, `gather` and `plan_lookups` spend is returned but never persisted.
- Make metering structural rather than per call site: every model call records tokens and cost against the tenant in one place (for example a single `model_calls`/spend record written by the adapters, or a wrapper applied in `container.py`), and every entry point that starts model work checks `over_cap` before calling. Use the existing price table (`domain/shared/prices.py`); unpriced models are recorded as unpriced, which the cap already treats as blind.
- Include the new records in the daily spend sum (`infrastructure/db/spend.py` `_BILLED`) so `over_cap` and `GET /v1/spend` see them.
- Keep `daily_usd_cap` default as it is (owner's instruction); this task makes the numbers true, it does not change the limit.
- Tests: each adapter's call produces a spend record with tokens; the mail look and gather are billed; `over_cap` counts the new records; an over-cap tenant's mail look does not call the model.
