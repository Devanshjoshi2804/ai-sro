# Small Package Operations policies

The Small Package Operations (SMLPKGOPR) policies determine which options are available on Small Package Operations in the SCE client. When you configure SMLPKGOPR policies, you can specify the following information:

-   The behavior and options available on the Print Package Labels window in the SCE client
-   Whether a parcel shipment is processed when the shipment is closed
-   Whether carrier changes are permitted on the Small Package Operations window and which printer will be used to print paperwork generated by Small Package Operations
-   The behavior and options available on the Print Paperwork window in the SCE client

You use Policy Maintenance or Policy Maintenance - Override to maintain SMLPKGOPR policies.

## Labels policies

The Labels (SMLPKGOPR/LABELS) policies control how the Print Package Labels window behaves and what options are available on it. The following Labels policies are available:

-   **Default (SMLPKGOPR/LABELS/DEFAULT)**: Defines the package label settings for shipments that do not match any existing carrier and service level-specific policies.
-   **Carrier and service-level specific (SMLPKGOPR/LABELS/<**_Carrier\_service level_**>)**: Defines the package label settings whenever a shipment's carrier code and service level (delineated by an underscore) match the policy. A carrier and service level must be defined on the Existing Carriers page.

You can configure the following DETAILS fields for these policies:

-   **Return String 1**: Text string used to label the check box on the Print Package Labels window that the user selects to print parcel labels manually. For example, Print Labels is the value for the Default policy and Print UPS Labels is the value for the carrier and service level specific UPS\_1DAY policy.

-   **Return Number 1**: Specifies whether the print parcel labels check box is selected (indicating to manually print parcel labels) when the Print Package Labels window opens. The following values are valid:
    -   **0**: Deselects the check box. This option is useful if you normally print labels automatically and only manually print labels as necessary, for example, when labels do not print automatically, such as due to a printer jam.
    -   **1**: Selects the check box. This option is useful if you always print labels manually.

## Defer shipment processing policy

The Defer shipment processing (SMLPKGOPR/MANIFEST-CLOSE-OPTIONS/DEFER-ALL-SHIPPING) policy controls whether a parcel shipment is processed when the manifest is closed or deferred until later. When deferred, shipments will not be processed during the closing of the manifest. Instead, shipment processing will be held until a request is received to process the shipment. This request can be initiated automatically by the Deferred Execution job defined and enabled on the Jobs page in the Console, or manually by clicking Ship Deferred on the Small Package Operations window.

When a parcel shipment is processed, Warehouse Management processes the following tasks:

-   Updates the parcel's manifest status to Shipped
-   Creates all of the necessary shipping structures, such as stops and carrier moves
-   Loads the stops
-   Closes and dispatches the trailer
-   Sends transactions, if configured to do so, to the host system to indicate that the parcel has been shipped

Deferring a shipment is useful if you regularly perform parcel processing. A manifest with many parcel shipments will take time to process when the manifest is closed, which can delay the closing and dispatching of the parcel shipping trailer.

**Note**: It is suggested that you enable this policy.

You can configure the following DETAILS field for this policy:

-   **Return Number 1**: Specifies whether shipments will be deferred (enabled). A value of 1 is enabled, 0 is disabled.

## Allow carrier change policy

The Allow carrier change (SMLPKGOPR/MISCELLANEOUS/ALLOW-CARRIER-CHANGE) policy controls whether carrier and service level changes are permitted (enabled) when performing parcel shipment operations. When this policy is enabled, and changes are also allowed on the parcel's order, the **Chg Carrier** button is displayed on the Small Package Operations window.

You can configure the following DETAILS field for this policy:

-   **Return Number 1**: Specifies whether carrier changes are permitted (enabled). A value of 1 is enabled, 0 is disabled.

## Paperwork printer address policy

The Paperwork printer address (SMLPKGOPR/MISCELLANEOUS/PAPERWORK-PRINTER-ADDRESS) policy controls which printer is used to print paperwork (automatically or manually by clicking the **Paperwork** button) generated by the Small Package Operations window for a given workstation. You define a printer address to be used with any workstation (DEFAULT) and can define one or more policy details to associate a specific workstation with a printer.

You can configure the following DETAILS fields for this policy:

-   **Return String 1**: Workstation from which the paperwork will be sent. The following values are valid:
    -   **DEFAULT**: Any workstation that is not defined as having an associated printer in the policy details.
    -   _<_WS-XX_>_: Workstation name as defined on the Workstation page.
-   **Return String 2**: Printer name, as defined on the Printers page, to which the paperwork will be sent from the workstation indicated in **Return String 1**.

## Paperwork policies

The Paperwork (SMLPKGOPR/PAPERWORK) policies control how the Print Paperwork window in the SCE client behaves and what options are available on it. The Print Paperwork window is displayed when you **click Print Paperwork** on the Small Package Operations window.

**Note**: To configure the Print Package Labels window in the SCE client, see [Labels policies](#Labels_policies).

The following Paperwork policies are available:

-   **Default (SMLPKGOPR/PAPERWORK/DEFAULT)**: Defines the paperwork settings used whenever a carrier-specific policy does not exist.
-   **Carrier-specific (SMLPKGOPR/PAPERWORK/<Carrier>)**: Defines the paperwork settings that are to be used whenever the shipment's carrier, defined on the Existing Carriers page, matches the policy.

You can configure the following DETAILS fields for these policies:

-   **Return String 1**: Text string used to label the check box on the Print Paperwork window that the users selects to print the paperwork. For example, Print Manifest is the value for the Default policy and Print Manifest-UPS is the value for the UPS policy.
-   **Return Number 1**: Specifies whether the print paperwork check box is selected (indicating to manually print parcel paperwork) when the Print Paperwork window opens. The following values are valid:

-   **0**: Deselects the check box. This option is useful if you normally print paperwork automatically and only manually print paperwork as necessary, for example, when the manifest does not print automatically, such as due to a printer jam.
-   **1**: Selects the check box. This option is useful if you always print paperwork manually.
