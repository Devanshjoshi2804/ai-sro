Event Management

In this topic
  • Event Management
    • Configure Event Management integration
    • Event Management fields

You use the Event Management integration page to enable and configure the integration of Event Management. Event Management is a web-based application that helps you manage your logistics operations by alerting you to critical application and operational events at the time that they occur. Event Management may be installed in a separate instance, or in the same instance as Warehouse Management.

User and role assignments for a disabled integration

If Event Management is integrated with and installed in the same instance as Warehouse Management, and you disable the integration, the Event Management functionality is disabled. To prevent users from accessing disabled functionality, remove Event Management menus from the users or roles to which they are assigned.

In addition, if custom menus or groups were created using Event Management pages, or custom pages were created using Event Management resources, you must also remove those menus, groups, and pages from the users and roles to which they are assigned. See Authorization.

Alternatively, Event Management can be uninstalled to permanently remove the Event Management menus, groups, pages, and resources. See the Warehouse Management Installation Guide.

Configure Event Management integration

  1. Select Configuration > Integration > Event Management.

    Note: If you disable an installed instance of Event Management, then Event Management functionality is also disabled.

  2. Enter information in the Event Management fields.
  3. Click Save.

Event Management fields

Field Description
Enable Event Management

If Enabled, then the configuration settings will take effect. Also, if Event Management is installed, Event Management functionality becomes available for use in Warehouse Management.

If Disabled, then Event Management processing functions will not take place. Also, if Event Management is installed, then Event Management functionality is disabled. For information on managing user and role access to disabled functionality, see Event Management integration.
Source System

Identifier for the current application (Warehouse Management) that is the source of alerts that are sent to Event Management. The value in this field is not used in any functional processing; instead, this value is used as the value for the Source System field on an alert notification in Event Management. The source of an Event Management alert can help users identify and focus on the alerts from a specific application. For example, if alerts are being sent to Event Management from Warehouse Management and from other systems, you could define this value as WM. Whenever information is sent to Event Management from Warehouse Management, the alert subscriber can immediately identify that the source system is WM and not one of the other systems. This field has a maximum of 30 characters.

If No, information is not sent to Event Management.

Handling Unit Feature Out of Threshold

If Yes, information is sent to Event Management whenever the value of a handling unit feature falls outside threshold values set for the feature. For example, if your handling unit feature is transport equipment temperature, you can set threshold values for that feature; if the transport equipment temperature is higher or lower than the threshold values, and this policy is enabled, then a notice is sent to Event Management. This event only applies to handling unit types configured with the Transport Equipment handling unit category.

If No, information is not sent to Event Management.

Handling Units at Location Below the Stocking Level

If Yes, information is sent to Event Management whenever the quantity of a specified handling unit type falls below the minimum value defined for the location. For example, if a location is configured to have a minimum of 15 handling units of a certain handling unit type and the quantity of handling units in the location falls to 14, then a notification is sent to Event Management if this policy is enabled. This event only applies to handling unit types configured with the Inventory handling unit category.

If No, information is not sent to Event Management.

Slow Moving Handling Units

If Yes, information is sent to Event Management whenever a handling unit is not moved within the specified number of hours. For example, if you define a slow moving handling unit as one that has not moved in 10 hours and a handling unit is stationary for longer than 10 hours, then a notification is sent to Event Management if this policy is enabled. This event only applies to handling unit types configured with the Inventory handling unit category.

If No, information is not sent to Event Management.

Background Workflow Failed

If No, information is not sent to Event Management.

Inventory Workflow Failed

If Yes, information is sent to Event Management whenever an error is returned during the processing of a server command for an inbound or outbound workflow.

If No, information is not sent to Event Management.

Non-Inventory Workflow Failed

If Yes, information is sent to Event Management whenever an error is returned during the processing of a server command for warehouse equipment, transport equipment, or a production workflow.

If No, information is not sent to Event Management.

Zone Contains Stranded Inventory

If Yes, information is sent to Event Management whenever pickable inventory becomes stranded. Inventory can become stranded (not pickable) if an operator overrides a warning message and deposits inventory in a location in a zone that does not support picking the unit of measure (UOM) that was deposited. For example, if a zone supports only picking pallets and an operator overrides a warning message and deposits cases of inventory to the location, those cases would be stranded because cases are not pickable in that location.

If No, information is not sent to Event Management.

Count Back Discrepancy

If Yes, information is sent to Event Management whenever there is a discrepancy when an operator performs a count back. Count back is a picking verification to capture the quantity that is remaining in a pallet or location in addition to the quantity being picked from the pallet.

If count back is required for an operator picking less than a full pallet, a count back discrepancy exists when the remaining quantity does not match the expected quantity. If this policy is enabled, then whenever there is a count back discrepancy, a notification is sent to Event Management.

If No, information is not sent to Event Management.

Location Status in Error

If Yes, information is sent to Event Management whenever a location within your warehouse is placed in an error condition (occurs when the Location Status is Inventory Error). This means that a discrepancy was found between the items in the location and the item information for that location; for example, a different physical quantity than the quantity indicated in the application. When a location is in error, inventory cannot be allocated from or putaway (deposited) in it. Consequently, you might want to know about locations in error quickly so that the problem can be resolved and the location reset to a usable status.

If No, information is not sent to Event Management.

Lot Expiration Warning

If Yes, information is sent to Event Management whenever a lot for which inventory exists in the warehouse is nearing its expiration date. You specify the number of days in advance of the expiration date and Event Management is notified.

If No, information is not sent to Event Management.

Low Inventory

If Yes, information is sent to Event Management whenever the inventory level for an item in the facility falls below the reorder point defined for the item. If Low Inventory is enabled, then the application periodically checks each item to see if the amount of inventory in your facility is less than the amount set as the re-order point defined for the item. If it is, then the application notifies Event Management of low inventory.

If No, information is not sent to Event Management.

Work Order with Unassigned Detail Started

If Yes, information is sent to Event Management whenever a user starts a work order that has one or more details that have not yet been assigned to a production station.

If No, information is not sent to Event Management.

Work Order Automatically Created

If Yes, information is sent to Event Management whenever the application automatically generates a work order from a bill of material (BOM) that has the Auto-generate Work Order check box selected. Work orders are automatically created from a BOM when an order, work order, or replenishment for the top-level item is allocated, and the application cannot find the inventory in the facility.

Work orders are also automatically created when an order line that specifies order explosion (the Item Download Type field, PRT_DL_TYP, is set to K for kit) is downloaded from the host system. Order explosion is an order processing mode in which an order for a top-level item is downloaded from the host system, and the application converts the order into an order for the component items, as defined by a BOM for the top-level item.

If No, information is not sent to Event Management.

Resize Carton

If Yes, information is sent to Event Management whenever a carton is resized for picking. The Carton Resize function enables you to assign a different carton code to an existing carton number being used for picking. If you are picking into a carton and realize it is too large or too small for the order, you can reassign a carton code to the existing carton number, which provides you with the proper dimensions to complete the picks.

If No, information is not sent to Event Management.

Item Lot Created or Changed by Download

If Yes, information is sent to Event Management when the application successfully creates or updates an item lot record due to a status change request sent from the host. Warehouses may receive a request to update the default receiving status of inbound inventory that matches the attributes defined in the request, including the item and lot combination.

For example, in a third-party logistics environment, assume that a warehouse receives Client A's inventory for a specific item lot combination in the Available status. If Client A discovers an issue with the item lot, the client can send a request to update the status assigned to that item lot combination so that when additional inventory is received, the application applies the new inventory status. In addition, the application attempts to update existing inventory in the warehouse with the same item lot combination to the new inventory status.

If this field is set to Yes, information is sent to Event Management only when the application receives the transaction and successfully updates (if the record exists) or creates a new item lot record with the attributes provided in the transaction. This event is not dependent on whether the application successfully processes the actual status change for existing inventory in the warehouse that matches the item lot record.

The event contains the inventory status change request details, of which the following are required:

  • Warehouse
  • Client
  • Item
  • Lot
  • From Status
  • To Status

If No, information is not sent to Event Management.

Inventory Status Changed by Download

If Yes, information is sent to Event Management when the application successfully processes an inventory status change due to a request received from the host to update the default status of inventory received with a certain item and lot combination.

Warehouses may receive a request to update the default receiving status of inbound inventory that matches the attributes defined in the request, including the item and lot combination.

For example, in a third-party logistics environment, assume that a warehouse receives Client A's inventory for a specific item lot combination in the Available status. If Client A discovers an issue with the item lot, the client can send a request to update the status assigned to that item lot combination so that when additional inventory is received, the application applies the new inventory status. In addition, the application attempts to update existing inventory in the warehouse with the same item lot combination to the new inventory status. If enabled, this event is used to notify Event Management when the application successfully updates the status of existing inventory in the warehouse to the new inventory status.

The event contains the inventory status change request details, of which the following are required:

  • Warehouse
  • Client
  • Item
  • Lot
  • From Status
  • To Status

If No, information is not sent to Event Management.

Inventory Status Error During Change by Download

If Yes, information is sent to Event Management when the application cannot successfully process an inventory status change due to a request received from the host.

Warehouses may receive a request to update the default receiving status of inbound inventory that matches the attributes defined in the request, including the item and lot combination.

For example, in a third-party logistics environment, assume that a warehouse receives Client A's inventory for a specific item lot combination in the Available status. If Client A discovers an issue with the item lot, the client can send a request to update the status assigned to that item lot combination so that when additional inventory is received, the application applies the new inventory status. In addition, the application attempts to update existing inventory in the warehouse with the same item/lot combination to the new inventory status. If enabled, this event is used to notify Event Management when the application cannot successfully update the status of existing inventory in the warehouse to the new inventory status due to a processing error.

This alert can be sent, for example, if the application cannot process the status change because it would violate a mixing rule. The event contains the inventory status change request details, of which the following are required:

  • Warehouse
  • Client
  • Item
  • Lot
  • From Status
  • To Status

If No, information is not sent to Event Management.

New Item Created

If Yes, information is sent to Event Management whenever a new item is created with the Receivable field set to No. The Receivable field is set to No for an item to indicate that not all of the valid information that is needed to store and ship the item is available. Generally, this is the case when new item information is sent to Warehouse Management from a host system when the host system does not have all the necessary item information. Whenever an item is created that is not receivable, a notification is sent to Event Management.

If No, information is not sent to Event Management.

A customs consignment is set of customs-related information that is associated with a specific receipt of bonded inventory. This event is sent to prioritize the sending of customs consignment to the duty management application. If enabled, then whenever picking has occurred for bonded inventory and the customs consignment has not been processed, a notification is sent to Event Management

Cancellation of Order Sequence Pick

If Yes, information is sent to Event Management whenever a sequenced order pick is cancelled and either not reallocated, partially reallocated, or unsuccessfully reallocated. Picks for sequenced orders are planned to work assignments by item family set. Each order is planned to a specific slot on a master handling unit; and the slot is reserved for the order. If nothing is found in reallocation, the slot is reserved (not used) and the remaining picks for the handling unit are directed to the slots for which they were planned.

Carrier Capacity Warning

If Yes, information is sent to Event Management whenever the estimated number of pallets required for the shipments assigned to a particular carrier that have not yet been assigned to stops has exceeded your threshold limit. This information indicates that someone should contact the carrier to let them know that they need to send transport equipment to pick up the shipments.

For example, you can set the threshold to the number of pallets that fills a single piece of transport equipment. Whenever the threshold is exceeded, you know that you will soon have enough shipments ready to fill the transport equipment and should contact the carrier to send another. Then, while the carrier is en route and the operators finish staging the shipments, you can set up everything that you need to set up in the application before loading the transport equipment, such as a load and stops. You specify the number of pallets that needs to be exceeded before Event Management is notified.

This information lets the Event Management alert subscriber know that once the shipment is staged, it may need to be moved to a different ship staging location (the location that services the new carrier).
