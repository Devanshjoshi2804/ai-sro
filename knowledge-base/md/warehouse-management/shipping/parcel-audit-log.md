# Parcel Audit Log

The Parcel Audit Log page displays the transactions for each operation between Parcel Handler and the parcel application for a selected date or date range. The page also provides access to the request and response messages for each operation.

Transactions are captured for the following operations:

-   **Authentication**: This operation takes place when the authentication (JDA-PC-AUTHENTICATION) job is run. An authorization ticket is generated for integration with the parcel application. Connection details and credentials for the parcel application must be configured for the authentication job to run. To configure this policy, see [Configure Parcel Handler](../configuration/outbound/shipping/parcel-handler.md).
-   **Close**: This operation takes place when a manifest is closed. See [Close a manifest](parcel/procedures-for-parcels.md).
-   **Documents**: This operation takes place when paperwork is printed for a closed manifest. See [Print paperwork for a closed manifest](parcel/procedures-for-parcels.md).
    
-   **CARSRVATTRIBUTES**: This operation takes place when the fetch service conditions (FETCH-SERVICE-CONDITIONS) job is run. Service conditions and parameters are retrieved for carriers that are configured in the carrier list. See [Configure Parcel Handler](../configuration/outbound/shipping/parcel-handler.md).
-   **Labels**: This operation takes place when labels are printed for packages. See [Print a parcel label](parcel/procedures-for-parcels.md).
-   **Manifest**: This operation takes place when a package is manifested. See [Manifest a parcel](manifesting.md).
-   **Rate shop**: This operation takes place when rate shopping is performed to determine which carrier can provide the service in the shortest lead time or at the lowest price. See [Rate shopping for a parcel](parcel/parcel-concepts.md).
    
-   **Release**: This operation takes place when a held package is released. See [Release a held parcel](parcel/procedures-for-parcels.md).
-   **Update package**: This operation takes place when the weight or ship date is modified in a held package.
-   **Void**: This operation takes place when a package is removed from a manifest. See [Void a manifested parcel](parcel/procedures-for-parcels.md).

The request message is the XML document of the transaction sent from Parcel Handler to the parcel application. The response message is the XML document of the transaction returned to Parcel Handler from the parcel application. For transaction details, see the _Warehouse Management Parcel Handler Configuration Guide_.

If any error occurs during parcel processing, the Error Message column displays the status code and description (provided by the parcel application) for the failed operation. Error messages originate from the parcel application. If you cannot resolve the problem based on the content of the error message and a review of the request and response messages, see the documentation provided by the third-party parcel application.

## View the parcel audit log

**Note**: For transaction details, see the _Warehouse Management Parcel Handler Configuration Guide_.

1.  Select **Shipping > Parcel Audit Log**.
2.  In the date fields, select a specific date or date range, and time, and then click **Go** to display the operations that match your criteria.
3.  To filter the displayed results, enter search criteria.
4.  View information in the [Parcel Audit Log fields](#Parcel_Audit_Log_fields).
5.  To view the XML message sent from Parcel Handler to the parcel application, click **View Request**.
6.  To view the XML message returned from the parcel application to Parcel Handler, click **View Response**.

## Parcel Audit Log fields

 
| Field | Description |
| --- | --- |
| Inserted Date | Date and time at which the transaction was created. |
| Last Updated Date | Date and time at which the transaction was last updated. |
| Error Message | Information generated by the parcel application indicating the reason that the transaction failed. When a transaction fails, the error must be resolved, and the operation performed again. To diagnose an error, review the request and response messages, and determine whether a Warehouse Management configuration can resolve the error. Otherwise, refer to the definition of the status codes in the documentation provided by the parcel application. |
| Event Sequence | Unique event sequence generated by Integrator. |
| External Communication TAT | Sum of vendor turnaround time (TAT), network latency, and time taken for the request to leave Integrator and communicate with the parcel application. |
| Manifest Identifier | Internal tracking number assigned and used by the application to identify a manifest. A manifest list identifies all parcels that are shipped together on a piece of transport equipment by the parcel carrier. |
| Message Identifier | Unique identifier for a Parcel Handler operation. |
| Parcel Handling TAT | Sum of network latency and total time taken by the Parcel Handler, Integrator, and parcel application to process the request. |
| Parcel Identifier | Identifier for a parcel on which the operation is performed. The following operations are performed on a specific parcel: manifest, rate shop, release, update package, and void. A parcel identifier is not provided for operations that do not involve a specific parcel: authentication, close manifest, and print documents. |
| Operation | Parcel Handler operation that identifies the type of activity being performed. |
| Request Message | Click **View Request** to view the content of the XML message sent from Parcel Handler to the parcel application for the operation. |
| Response Message | Click **View Response** to view the content of the XML message returned back from the parcel application to Parcel Handler for the operation. |
| Seamless TAT | Sum of network latency and the time taken by Integrator and the parcel application to process the request. |
| Shipper | The shipper represents the entity and address (location) from which a parcel is shipped. The warehouse is the physical entity shipping parcels; however, for rating and manifesting purposes, individual buildings or clients can also be considered the shipping entity. Warehouse Management uses the shipper to indicate which parcel carrier shipper account (and, therefore, which set of rates) is to be used for manifesting and rating a parcel shipment.<br > Shipper identifiers are provided by the parcel application, and configured on the Parcel page in Warehouse Management. See [Configure parcel](../configuration/outbound/shipping/parcel.md). |
| Status | Status of the parcel operation. |
| User | User who performed the operation. |
| Vendor TAT | Total turnaround time (TAT) taken by the parcel application to process a request. |
