Standard Events

In this topic

    • Event Management
    • Integrator

The Event Management events that are described in the following topics are the standard events that can be generated by the Supply Chain Execution (SCE) applications with which Event Management integrates. You or an administrator can select the events for which you want Event Management to send alerts and alert notifications to you by subscribing to them on the Event Subscription page.

Event Management

Event Management sends the following standard events to itself:

  • EMS-EVENT-LIMIT: Sent whenever the number of raised events exceeds the limits set in the Event Limit policies.
  • EMS-HELD-ALERT-LIMIT: Sent whenever the number of held alerts exceeds the limit set in the Event Held Alert Limit policy.
  • EMS-TEST-UOM: Sent whenever a measurement unit or time zone conversion test has been performed. By default, this event is not available in the Event Management portal server (web-based) instance. To run the test, in the SCE client enable the corresponding policy in the Policy Maintenance window of the Event Management application instance, and then prime the event. Next, subscribe to the event. Finally, run the command, raise ems event for uom timezone test, which accepts the following optional parameter: metric_flg = 1.
  • SYSTEM-CONNECTION-FAILURE: Sent whenever a remote call to a server running an SCE application fails. This event means that Event Management was unable to connect to a remote server, and you need to find out why it is not connecting.

Integrator

Integrator (SCE) sends the following standard events to Event Management:

  • Generic inbound events:
    • INT-DWNLD_HAS_ERRORS (Download Has Errors): Sent whenever problems were discovered in a download from the execution system to Integrator, which caused the download to be placed in an error status.
    • INT-DWNLD_IS_EMPTY (Download is Empty): Sent whenever a download is received by Integrator without any identified interface document (IFD) transactions included.
  • Generic outbound events:
    • INT-FAILED_TO_SEND_IFDS (Failed to Send IFDs): Sent for each Integrator failure to send a communication set (one or more resulting IFDs) to a destination system, and the failed events are placed in a send error (SE) status.
    • INT-SYSTEM_SEND_FAILURE (System Sent Failure): Sent upon the first Integrator failure to send a communication set (one or more resulting IFDs) to a receiving system.
  • Execution system-specific inbound events:
    • INT-ASYNCEVTPROC-<EVT_ID>: Sent whenever the asynchronous event process cannot log an Integrator event.
    • INT-DWNLD_IFD_ERROR-<EVT_ID> (Download IFD Error): Sent whenever Integrator is unable to process an inbound IFD, and cannot generate a resulting IFD.
    • INT-TBLTOEVT_ERRORS-<EVT_ID> (Event Log Generation Error): Sent whenever Integrator fails to generate an event log to send to Event Management.
  • Execution system-specific outbound event:
    • INT-IFD_CREATION_ERROR-<EVT_ID> (IFD Event Creation Error): Sent whenever Integrator is unable to process an outbound IFD, or is unable to generate a resulting IFD to send to a receiving system.

Warehouse Labor Management

Warehouse Labor Management sends the following standard events to Event Management:

  • General events:
    • LM-CASE-DISCRETE-TIME-NOT-FOUND: Sent whenever a case piece record is not found for a specific location, machine, cube, weight, and location type.
    • LM-CASE-TYPE-NOT-FOUND: Sent whenever a case type is not found for a specific cube and weight.
    • LM-INACTIVE-USER: Sent whenever information is received for a user that has a status of Inactive.
    • LM-INVALID-DATA-IN-TRANSACTION: Sent whenever an invalid download or sign-on field, such as client or work type, is received.
    • LM-JOB-CODE-MAPPING-NOT-FOUND: Sent whenever a job code is not mapped, or is mapped to an invalid work area, aisle, client, or customer.
    • LM-LOW-PERFORMANCE: Sent whenever it is determined that an employee’s performance has fallen below a certain level. You can specify the threshold that determines if an employee is a low performer.
    • LM-PALLET-DISCRETE-TIME-NOT-FOUND: Sent whenever a pallet time measurement unit (TMU) record is not found for a specific location, machine, and location type.
    • LM-PROCESS-LOG-ALERT: Sent whenever a warning or error message is generated and stored to the process log table. Details describing the cause of the error are also provided.
    • LM-QUALITY-ERROR-RESOLUTION-FAILED: Sent whenever resolution of a quality error will not be retried.
    • LM-REPORTCARD-ALERT: Sent whenever a disciplinary or reward action is required based on a report card score received by a user.
    • LM-REPORTCARD-PROGRESSION: Sent whenever a user is automatically assigned to another report card.
    • LM-UNMEASURED-APPROVAL-REQUEST: Sent whenever an assignment is in a pending state following a user’s request for unmeasured time.
    • LM-USER-NOT-ON-SCHEDULE: Sent whenever a user signs on to an assignment during a time in which the user is not scheduled to work.
  • Time and incentives events:
    • CT-EARLY-PUNCHIN: Sent whenever an employee clocks in early based on the employee’s schedule. You can specify the number of minutes before clock in that employees are considered early.
    • CT-EARLY-PUNCHOUT: Sent whenever an employee clocks out early for a shift. You can specify the number of minutes before clock out that employees are considered early.
    • CT-LATE-PUNCHIN: Sent whenever an employee clocks in late. You can specify the number of minutes after clock in that employees are considered late.
    • CT-MISSING-PUNCH: Sent whenever it is determined that an employee is missing a clock punch. For example, an employee may have clocked out for lunch, but there is no corresponding clock in from lunch.
    • CT-PUNCHIN-NO-ACTIVE: Sent whenever an employee has clocked in but has not yet signed on to an active assignment. You can specify the number of minutes after clock in to let users begin an assignment before Event Management is notified.
    • CT-SCHED-NO-PUNCHIN: Sent whenever an employee is scheduled but has not yet clocked in.
    • CT-SIGNON-NO-PUNCHIN: Sent whenever an employee is actively working on an assignment, but has not clocked in, or there is no record of the clock in.

Warehouse Management

Warehouse Management sends the following standard events to Event Management:

  • Appointment events:
    • WMD-EARLY-TRLR: Sent whenever transport equipment has arrived for check-in prior to its scheduled appointment at a dock door. You can specify the number of minutes before the scheduled appointment time that arriving transport equipment is considered early and Event Management is notified.
    • WMD-LATE-TRLR: Sent whenever transport equipment has arrived late for its scheduled appointment at a dock door. You can specify the number of minutes after the scheduled appointment time that arriving transport equipment is considered late and Event Management is notified.
  • General events:
    • WMD-FAIL-BCKGRND-SERVICE: Sent whenever an error is returned during the processing of a MOCA command for a background workflow.
    • WMD-FAIL-INV-SERVICE: Sent whenever an inventory workflow fails.
    • WMD-FAIL-NONINV-SERVICE: Sent whenever a non-inventory workflow fails.
  • Handling unit tracking events:
    • WMD-LOW-ASSET-ALERT-AT-LOC: Sent whenever the serialized handling unit count falls below the stocking level configured for the location.
    • WMD-SLOW-MOVING-ASSETS: Sent whenever the number of hours it takes for a handling unit to be moved from its source to its destination exceeds the maximum number of hours configured for moving handling units.
  • Inventory control events:
    • WMD-AREA-STRANDED-INVENTORY: Sent whenever a user overrides a deposit location to a new deposit location where inventory will be or is not pickable. This event also notifies subscribers when a user modifies the unit of measure (UOM) levels on the area in a way that causes existing loads in the area to be non-pickable.
    • WMD-AUTO-WORK-ORDER-CREATED: Sent whenever a work order is created automatically from a Warehouse Management bill of material (BOM).
    • WMD-CARTON-RESIZE: Sent whenever a carton is resized using the Carton Resize application. This information enables you to know how many times a carton was resized so that you can take appropriate corrective action, if necessary.
    • WMD-CARTONIZATION-FAILED: Sent whenever the cartonization process fails to cartonize a shipment.
    • WMD-COUNT-BACK-DISCREPANCY: Sent whenever a count back is performed that does not match the application quantity.
    • WMD-ERRORED-LOCATION: Sent whenever a location within your warehouse is placed in an errored condition, meaning that a discrepancy was found between the items in the location, and the item information within Warehouse Management.
    • WMD-INVADJ-APPROVAL: Sent whenever a pending inventory adjustment exceeds a threshold defined for the user, role, client, client group, or warehouse, and requires supervisor approval in order to be processed.
    • WMD-LOT-EXPIRING: Sent whenever a lot is approaching expiration. The event can be configured with a threshold value for the number of days until expiration.
    • WMD-LOW-INVENTORY: Sent whenever the inventory level for a specific item falls below the reorder point.
    • WMD-NEW-PART-CREATED: Sent whenever a new item is created. This event usually indicates that the dimensional information was not available when the item was first created or downloaded from the host. The dimensional information needs to be entered into the application the first time the item is received into the warehouse at which time the actual dimensions can be determined.
    • WMD-OUTAUD-DISCREPANCY: Sent whenever an outbound audit is completed with discrepancies. A discrepancy occurs when the attribute value entered by the operator is different from what the application expected.
    • WMD-WORK-ORDER-WITH-UNASSIGNED-DETAIL-STARTED: Sent whenever a work order has been started, but it still has one or more work order lines that have not yet been assigned to a production station.
  • Picking events:
    • WMD-CANCEL-NO-SUCC-REALLOC-FOR-SEQUENCE-ORDER: Sent whenever a sequenced order pick is cancelled and either not reallocated, partially reallocated, or unsuccessfully reallocated.
    • WMD-CANCEL-PICK: Sent whenever a pick is cancelled using a cancel code configured to raise an Event Management event. The Cancel Pick policy must also be enabled to send this event when a pick is cancelled.
    • WMD-CSTMS-CONSIGNMNT-DTY-PROC: Sent whenever picking has occurred for bonded inventory, and the customs consignment is not yet duty processed.
    • WMD-INV-RDT: Sent whenever inventory on a radio data terminal (RDT) has not been processed after a specified length of time.
    • WMD-RPL-ORDER-CUT: Sent whenever a pick replenishment is cancelled due to application timeout or error conditions. Corrective action is needed to regenerate this task.
    • WMD-RPL-WORK-ORDER-CUT: Sent whenever a work order replenishment is cancelled due to application timeout or error conditions. Corrective action is needed to regenerate this task.
    • WMD-VOICE-PICK-ERROR: Sent whenever a voice picking error occurs.
  • Receiving events:
    • WMD-HOT-TRLR: Sent whenever a receiving trailer is labeled hot, meaning that it contains product needed to complete an order.
    • WMD-INTR-INV-UPDATE: Sent whenever a problem occurred while creating the advanced shipment notification (ASN) inventory.
    • WMD-OVER-RCPT: Sent whenever an amount of inventory received from a trailer is greater than the expected quantity.
    • WMD-OVRCPT-THRES: Sent whenever a user attempts to over receive inventory above the configured threshold.
    • WMD-TRAILER-CLOSE-PUTAWAY-FAILURE: Sent whenever the application fails to create directed work to store staged inventory when configured to do so. This event is only used if the application is configured to create directed work automatically for staged inventory after an RF operator closes transport equipment.
    • WMD-TRLR-DSCRPNCS: Sent whenever a user attempts to close a receiving trailer with discrepancies but is unable to because of role permissions.
    • WMD-UNDR-RCPT: Sent whenever the amount of inventory received from a trailer is less than the expected quantity.
  • Shipping events:
    • WMD-AUTO-CLOSE: Sent whenever a parcel shipment, whose carrier is marked for automatic closure, fails to automatically close.
    • WMD-CAR-CAP-WARN: Sent whenever the demands for a less than truckload (LTL) shipment are potentially exceeding the load capacity of the trailer. You can specify the pallet threshold that needs to be exceeded before Event Management is notified.
    • WMD-CARTON-WEIGHT-OUT-TOLERANCE: Sent whenever a shipping container cannot be closed due to an out of tolerance weight issue. When the packing operator attempts to close a shipping container, an error occurs when the difference between the estimated and actual weight of the container exceeds the acceptable minimum or maximum tolerance limit. If the error occurs, the information is sent to Event Management.
    • WMD-CLOSE-TRAILER: Sent whenever a trailer is closed.
    • WMD-CREATE-CAR-MOVE: Sent whenever a traffic plan (carrier move, stop, shipment, or order) has been added to the application (downloaded or created manually) and is ready to be allocated and shipped. Although this event can be used in any application, it is especially helpful in an application where full traffic plans are downloaded from a host or transportation management system (TMS).
    • WMD-CUST-RECEIPT-DISCREPANCY: Sent whenever an order line is updated to indicate that a discrepancy exists between the quantity that was shipped and the quantity that the customer reported as received.
    • WMD-DFRD-SHIP-CHANGE: Sent whenever a change to a TMS-planned shipment has been deferred because the shipment is in process, and the change is not allowed to happen between allocation and staging. The change takes effect when the shipment is staged.
    • WMD-DFRD-SHIP-CHANGE-ERR: Sent whenever a change in shipment requested by a TMS has errored in Warehouse Management because the shipment is already picked and staged in the warehouse.
    • WMD-LATE-SHIP: Sent whenever a staged shipment has not been loaded onto a trailer after a specified number of hours and may ship late.
    • WMD-MANFST-ERROR: Sent whenever an error occurs in the manifest process.
    • WMD-MANUAL-STAGE: Sent whenever a pick is cancelled but the rest of a shipment is ready to be staged.
    • WMD-ORD-LATE-SHPDTE: Sent whenever a truck has been opened for receiving and contains inventory assigned to distributions with late ship dates that have already passed or may pass before the associated inventory is received and processed for the distribution order.
    • WMD-ORDER-AUTO-ALLOCATION: Sent whenever automatic allocation of an order line fails because of a download or a normal scheduled event.
    • WMD-ORDER-CANCELLATION-ERROR: Sent whenever the application fails to cancel an order line because picking has already started for the order line.
    • WMD-SHIPMENT-STATUS-CHANGE-NOTIFICATION: Sent whenever the application sends an Integrator transaction (SHIPMENT_STATUS_CHANGE) to notify the host that a client's shipment has reached a certain status.
    • WMD-SHORT-SHIP: Sent whenever a shipment line has been shipped short.
    • WMD-STALLED-SHIP: Sent whenever a shipment has been staged in your warehouse for more than a specified number of hours. You can specify the number of hours that need to pass before a shipment is considered stalled.
    • WMD-STRND-INTR-SHPMNT: Sent whenever in-transit information for a shipment has not been processed after a specified length of time. This informs a shipping site that the receiving site never received the ASN information.
    • WMD-WORK-ORDER-AUTO-ALLOCATION: Sent whenever automatic allocation of a work order line (detail) fails because of a download or a normal scheduled event.
  • Application-level event:
    • WMD-PURGE-SHPMNT-ERR: Sent whenever an attempt to purge shipments fails.
  • Vendor managed inventory (VMI) event:
    • WMD-INV-OWNERSHIP-TRNS: Sent whenever an inventory ownership transfer has occurred.
  • Work Management event:
    • WMD-DELETE-DIRECTED-WORK: Sent whenever a work request has been cancelled without being completed.
  • Warehouse Labor Management processing event:
    • WMD-LM-COMM-ERROR: Sent whenever Warehouse Management encounters errors in attempting to obtain data from Warehouse Labor Management.

Standard shared events

Multiple Blue Yonder Supply Chain Execution (SCE) applications send the following standard events to Event Management:

  • MCS-LOGIN-FAILURE: Sent whenever a user fails to log in to the application correctly.
  • MCS-USER-INTRUDER: Sent whenever a user is locked out of the application due to failing to log in correctly.
  • SAL-ADDR-VALID-DUE-TO-INVALID-LOC: Sent whenever an address is determined to be valid, but the validation was performed against an invalid country, state, city, and postal code combination. Only relevant if address validation is enabled.
  • SAL-ARC-ERROR: Sent whenever an archiving job fails to complete successfully.
  • SAL-BATCH-DONE: Sent whenever a batch job is completed.
  • SAL-BATCH-MSG-LOG-FAIL: Sent whenever the batch message log is not running.
  • SAL-PRO-NUM-BLOCK-THRESHOLD: Sent whenever the number of available PRO numbers has reached the user-defined threshold.
  • SAL-PRO-NUM-UNAVAILABLE: Sent whenever a PRO number is not available.
  • SAL-TBLSPC-EXTENTS: Sent whenever a database tablespace has exceeded the specified threshold of extents. You can specify the number of extents allowed before Event Management is notified.
  • SAL-TBLSPC-FULL: Sent whenever a database tablespace is about to cross the specified threshold for being considered nearly full. You can specify the maximum tablespace percentage used before Event Management is notified.
