# Event Management policies

The Event Management (EMS) policies control whether Event Management is installed on the application server and how Event Management operates (if installed). For a list of events that can be generated by the applications that integrate with Event Management, see [Standard events](event-management-policies/standard-events.md).

You use Policy Maintenance to maintain Event Management policies.

**IMPORTANT**: These policies are global and cannot be overridden by warehouse.

## EMS installed policy

The EMS installed (EMS/INSTALLED/INSTALLED) policy controls whether Event Management is installed in the application, allowing events to be raised.

**IMPORTANT**: If you disable this policy, Event Management does not log data or raise events.

You can configure the following DETAILS field for this policy:

-   **Return Number 1**: Specifies whether the policy is enabled. A value of 1 is enabled, 0 is disabled. This policy is enabled by default.

## EMS file attachments path policy

The EMS file attachments path (EMS/FILE-ATTACHMENTS/PATH) policy defines the directory on the Event Management server where file attachments will be stored.

You can configure the following DETAILS field for this policy:

-   **Return String 1**: Path to the location on the Event Management server where event files are saved. The default value is **$LESDIR/files/hostout**.

## EMS EVENTS-INT\_STUB policies

The EMS EVENTS-INT-STUB policies are used as templates for the Integrator events sent to Event Management.

**IMPORTANT**: The EMS EVENT-INT-STUB policies cannot be configured. Use the EMS Integration-Events policies to configure how Integrator event information is sent to Event Management. For more information, see [Integration-events policies](#Integration-events_policies).

## EMS events policies

Several pre-configured EMS events are provided for the Blue Yonder applications that integrate with Event Management. These events vary between Blue Yonder applications. See [Standard events](event-management-policies/standard-events.md).

In addition, each Blue Yonder application can be configured to work with Event Management by defining the event information that is sent to Event Management.

### Archive purge error policy

The Archive purge error (EMS/EVENTS/SAL-ARC-ERROR) policy determines whether information is sent to Event Management whenever an error occurs during archiving or purging.

You can configure the following DETAILS fields for this policy:

-   **Return Number 1**: Specifies whether the policy is enabled. A value of 1 is enabled, 0 is disabled.

-   **Return String 1**: Valid MOCA server command used to send an event to Event Management. The default value is raise ems event for archive error.

**IMPORTANT**: Do not change this value without first consulting with your Blue Yonder project team.

### Deferred command execution failed policy

The Deferred command execution failed (EMS/EVENTS/SAL-DEFERRED-EXEC-FAILED) policy determines whether information is sent to Event Management whenever a deferred command errors on execution.

You can configure the following DETAILS fields for this policy:

-   **Return Number 1**: Specifies whether the policy is enabled. A value of 1 is enabled, 0 is disabled.

-   _Return String 1_: Valid MOCA server command used to send an event to Event Management. The default value is raise ems event for failed deferred execution.

**IMPORTANT**: Do not change this value without first consulting with your Blue Yonder project team.

### Deferred command execution overdue policy

The Deferred command execution overdue (EMS/EVENTS/SAL-DEFERRED-EXEC-OLD) policy determines whether information is sent to Event Management whenever a deferred command does not execute in a specified amount of time.

You can configure the following DETAILS fields for this policy:

-   **Return Number 1**: Specifies whether the policy is enabled. A value of 1 is enabled, 0 is disabled.
    

**Note**: If this policy is enabled, then a valid integer needs to be entered in the **Return Number 2** field.

-   **Return Number 2**: Integer representing the number of hours that a scheduled deferred execution command has to process before it is considered late. The default value is 4.

-   **Return String 1**: Valid MOCA server command used to send an event to Event Management. The default value is raise ems event for stale deferred execution.

**IMPORTANT**: Do not change this value without first consulting with your Blue Yonder project team.

### EMS event limit policy

The EMS event limit (EMS/EVENTS/EMS-EVENT-LIMIT) policy determines whether information is sent to Event Management whenever an Event Management limit has been exceeded.

**Note**: This policy is only available in Event Management.

You can configure the following DETAILS fields for this policy:

-   **Return Number 1**: Specifies whether the policy is enabled. A value of 1 is enabled, 0 is disabled.
-   **Return String 1**: Valid controller server command used to send an event to Event Management. The default value is raise ems event for limit.

**IMPORTANT**: Do not change this value without first consulting with your Blue Yonder project team.

### Execute parallel command policy

The Execute parallel command (EMS/EVENTS/SAL-EVENT-PARALLEL) policy determines whether information is sent to Event Management whenever an execute parallel command fails with a status other than success (0) or no rows affected (510). The execute parallel command executes commands across multiple servers at the same time.

You can configure the following DETAILS fields for this policy:

-   **Return Number 1**: Specifies whether the policy is enabled. A value of 1 is enabled, 0 is disabled.
-   **Return String 1**: Valid MOCA server command used to send an event to Event Management. The default value is raise ems event for execute parallel.

**IMPORTANT**: Do not change this value without first consulting with your Blue Yonder project team.

### Security intruder detected policy

The Security intruder detected (EMS/EVENTS/MCS-USER-INTRUDER) policy determines whether information is sent to Event Management whenever a user is locked out of the application from not logging in correctly.

You can configure the following DETAILS fields for this policy:

-   **Return Number 1**: Specifies whether the policy is enabled. A value of 1 is enabled, 0 is disabled.
-   **Return String 1**: Valid MOCA server command used to send an event to Event Management. The default value is raise ems event for user intruder.

### System connection failure policy

The System connection failure (EMS/EVENTS/SYSTEM-CONNECTION-FAILURE) policy determines whether information is sent to Event Management whenever Event Management fails to connect to a remote server.

**Note**: This policy is only available in Event Management.

You can configure the following DETAILS fields for this policy:

-   **Return Number 1**: Specifies whether the policy is enabled. A value of 1 is enabled, 0 is disabled. This policy is enabled by default.
-   **Return String 1**: Valid MOCA server command used to send an event to Event Management. The default value is raise ems event for system connection failure.
    
    **IMPORTANT**: Do not change this value without first consulting with your Blue Yonder project team.
    

## EMS instant messenger policies

The EMS instant messenger (EMS/INSTANT-MESSENGER) policies define the values for an instant messenger alert message configuration.

### Connection information policy

The Connection information (EMS/INSTANT-MESSENGER/CONNECTION-INFORMATION) policy defines the connection details for the instant messenger service.

You can configure the following DETAILS fields for this policy:

-   **Return String 1**: Instant messenger Service URL, such as http://www.gmail.com.
-   **Return String 2**: Host name of the receiving messaging service, such as talk.google.com.
-   **Return Number 1**: Event Management XMTP port value.

### IM login policy

The IM login (EMS/INSTANT-MESSENGER/IM-LOGIN) policy defines the login credentials that Event Management is to use when communicating with an instant messaging service; for example, to send an instant message alert notification.

You can configure the following DETAILS fields for this policy:

-   **Return String 1**: Instant messaging login identifier, such as the user name.
-   **Return String 2**: Instant messaging password for the user identifier specified in the **Return String 1** field.

### Lead message policy

The Lead message (EMS/INSTANT-MESSENGER/LEAD-MESSAGE) policy defines the first line of text that is displayed in all alert instant messages. The alert message then follows the lead message.

You can configure the following DETAILS field for this policy:

-   **Return String 1**: Standard text that begins each alert instant message, such as THIS IS AN AUTOMATED INSTANT MESSAGE FROM EMS - PLEASE DO NOT RESPOND.

### Tracing policy

The Tracing (EMS/INSTANT-MESSENGER/TRACING) policy controls whether tracing is enabled for the alert instant messenger. The trace file is written to and stored in the **$LESDIR/log** directory.

You can configure the following DETAILS fields for this policy:

-   **Return Number 1**: Specifies whether the policy is enabled. A value of 1 is enabled, 0 is disabled. This policy is disabled by default.
-   **Return String 1**: Name of the tracing log file on the Event Management server. The default value is **ems\_instant\_messenger.log**.

## EMS limits policies

The EMS limits (EMS/LIMIT-PROCESSING) policies determine the Event Management events to limit, the number of notifications (alerts) that Event Management accepts for a specific event, and how often Event Management checks for event limit violations.

**Note**: The EMS limits policies are only available in Event Management.

### Alerts being limited policy

The Alerts being limited (EMS/LIMIT-PROCESSING/SEND-ALERTS) policy determines the number of notifications (alerts) that Event Management can process at one time. This policy allows you to manage your SMTP server resources by limiting the number of alerts that are processed. Since the limit that you specify can prohibit Event Management from sending alerts out on a timely basis, Event Management collects alerts to be processed and sorts them based on priority and age. Highest priority alerts are processed first.

You can configure the following DETAILS field for this policy:

-   **Return Number 1**: Integer representing the maximum number of alerts that are processed at one time. The default value is 101.

### Events being limited policy

The Events being limited (EMS/LIMIT-PROCESSING/RAISED-EVENTS) policy determines which Event Management event is limited, the number of times the event can be sent, and how long the event limit applies. When the specified event limit is exceeded, the associated alerts are logged in to Event Management with a hold status and are not processed until an Event Management administrator releases them manually.

You can configure the following DETAILS fields for this policy:

**Note**: There are three default policy details configured for this policy.

-   **Sort Sequence**: Integer representing the application-generated order in which the limit is applied. The default values are 10, 15, and 20.
-   **Return String 1**: Unique identifier of the Event Management event to limit, or a priority level of all events to limit. The default values are PRIORITY1, PRIORITY2, and PRIORITY3.
    
    **Note**: To apply the limitation to a specific Event Management event, enter the event name. To apply the limitation to all Event Management events based on their priority level, enter the priority level (such as PRIORITY1, PRIORITY2, or PRIORITY3).
    
-   **Return Number 1**: Integer representing the maximum number of times the Event Management event can be sent in a specific time frame. The default value is 101.
-   **Return Number 2**: Integer representing the number of minutes for which the Event Management event limit applies. The default is 10.

### Iterations between limit checks policy

The Iterations between limit checks (EMS/LIMIT-PROCESSING/ITERATIONS) policy determines how many events are sent to Event Management before Event Management checks for violations of the Alerts being limited or Events being limited policies.

You can configure the following DETAILS field for this policy:

-   **Return Number 1**: Integer representing the number of events sent to Event Management that triggers Event Management to check for alert and event limit violations. The default value is 51.

## EMS miscellaneous policies

The EMS miscellaneous (EMS/MISCELLANEOUS) policies control required Event Management information.

**Note**: The EMS miscellaneous policies are only available in Event Management.

### Check for duplicate events policy

The Check for duplicate events (EMS/MISCELLANEOUS/CHECK-ALL-EVENTS-FOR-DUPLICATES ) policy determines whether Event Management will check every raised event for duplication using the event name, key value, and client ID. When this policy is disabled, only alerts that require acknowledgments are checked for duplication.

You can configure the following DETAILS field for this policy:

-   **Return Number 1**: Specifies whether Event Management checks for duplicate events. A value of 1 is enabled, 0 is disabled. The policy is enabled by default.

### Default locale policy

The Default locale (EMS/MISCELLANEOUS/DEFAULT-LOCALE) policy determines the locale ID used as the default by Event Management.

You can configure the following DETAILS field for this policy:

-   **Return String 1**: Unique identifier of the locale ID used by Event Management. The default value is US\_ENGLISH.

### From email policy

The From email (EMS/MISCELLANEOUS/FROM-EMAIL) policy defines the email address from which Event Management alerts are sent. This email address should clearly identify to the user that the message is being sent from Event Management.

You can configure the following field for this policy:

-   **Return String 1**: Email address from which event alerts are sent.

### Prime all new events policy

The Prime all new events (EMS/MISCELLANEOUS/PRIME-EVENTS) policy determines whether Event Management automatically primes events sent from the execution system.

You can configure the following DETAILS field for this policy:

-   **Return Number 1**: Specifies whether Event Management automatically primes events. A value of 1 is enabled, 0 is disabled. The policy is enabled by default.

### SMTP host server policy

The SMTP host server (EMS/MISCELLANEOUS/HOSTNAME) policy determines the name of the SMTP server used by Event Management.

You can configure the following DETAILS field for this policy:

-   **Return String 1**: Name representing the SMTP server to which Event Management sends event alerts.

A valid SMTP server name is required to receive alerts from Event Management.

### Source-system policy

The Source-system (EMS/MISCELLANEOUS/SOURCE-SYSTEM) policy determines the source application for the Event Management transactions that are sent to Event Management.

You can configure the following DETAILS field for this policy:

-   **Return String 1**: Name representing the source application for the Event Management transactions that are sent Event Management.

## Integration-events policies

The Integration-events policies control Event Management events that occur during integration to external applications.

**Note**: If you do not integrate with Event Management, and if you did not indicate a host and port number for Event Management during the server installation process, these policies are disabled and no event information is sent to Event Management.

### Inbound EMS events download has errors policy

The Inbound EMS events download has errors (EMS/EVENTS-INT-INBOUND/INT-DWNLD\_HAS\_ERRORS) policy determines whether information is sent to Event Management whenever a download is placed in error status.

You can configure the following DETAILS field for this policy:

-   **Return Number 1**: Specifies whether the policy is enabled. A value of 1 is enabled, 0 is disabled.

### Inbound EMS events download is empty policy

The Inbound EMS events download is empty (EMS/EVENTS-INT-INBOUND/INT-DWNLD\_IS\_EMPTY) policy determines whether information is sent to Event Management whenever a download is created without any of the IFDs that are identified in Integrator.

You can configure the following DETAILS field for this policy:

-   **Return Number 1**: Specifies whether the policy is enabled. A value of 1 is enabled, 0 is disabled. The policy is enabled by default.

### Inbound EMS events download IFD creation error policy

The Inbound EMS events download IFD creation error (EMS/EVENTS-INT-STUB/INT-STUB-DWNLD\_IFD\_ERROR) policy determines whether information is sent to Event Management whenever a Integrator Event (with an asynchronous delivery - unusual setup) encounters an IFD error that was logged from a download.

You can configure the following DETAILS field for this policy:

-   **Return Number 1**: Specifies whether the policy is enabled. A value of 1 is enabled, 0 is disabled. The policy is enabled by default.

### Asynchronous event to process EMS events policies

The Asynchronous event to process EMS events (EMS/EVENTS-INT-ASYNCEVT/INT-ASYNCEVTPROC-<EVT\_ID>) policies determine whether information is sent to Event Management whenever a failure occurs with an Integrator event that is being processed by the asynchronous event process.

**Note**: <EVT\_ID > represents the Integrator event ID. The event ID is defined by the execution system's Event Management filter components.

You can configure the following DETAILS field for these policies:

-   **Return Number 1**: Specifies whether the policy is enabled. A value of 1 is enabled, 0 is disabled. The policy is enabled by default.

### Table to event process EMS events policy

The Table to event process EMS events (EMS/EVENTS-INT-STUB/INT-STUB-TBLTOEVT\_ERRORS) policy determines whether information is sent to Event Management whenever a failure occurs with a Integrator event that is being processed by the table to event process.

You can configure the following DETAILS field for this policy:

-   **Return Number 1**: Specifies whether the policy is enabled. A value of 1 is enabled, 0 is disabled. The policy is enabled by default.

### Outbound IFD creation EMS events policy

The Outbound IFD creation EMS events (EMS/EVENTS-INT-STUB/INT-STUB-IFD\_CREATION\_ERROR) policy determines whether information is sent to Event Management whenever an IFD creation failure occurs with a Integrator event that is not associated with a download (outbound transaction).

You can configure the following DETAILS field for this policy:

-   **Return Number 1**: Specifies whether the policy is enabled. A value of 1 is enabled, 0 is disabled. The policy is enabled by default.

### Outbound send failure EMS events policy

The following Send Failure EMS Events (EMS/EVENTS-INT-OUTBOUND) policy determines whether information is sent to Event Management whenever a failure occurs with sending an outbound transaction:

-   INT-FAILED\_TO\_SEND\_IFDS
-   INT-SYSTEM\_SEND\_FAILURE

**IMPORTANT**: These policies are global and cannot be overridden by warehouse.

### EMS Event when IFDs sending failed in outbound transaction policy

The EMS Event when IFDs sending failed in outbound transaction (EMS/EVENTS-INT-OUTBOUND/INT-FAILED\_TO\_SEND\_IFDS) policy determines whether information is sent to Event Management whenever a communication set (one or more IFDs) was not sent to the destination application and the event is placed in the send error (SE) status.

You can configure the following DETAILS field for this policy:

-   **Return Number 1**: Specifies whether the policy is enabled. A value of 1 is enabled, 0 is disabled. The policy is enabled by default.

### EMS Event when eent sending failed in outbound transaction policy

The EMS Event when event sending failed in outbound transaction (EMS/EVENTS-INT-OUTBOUND/INT-SYSTEM\_SEND\_FAILURE) policy determines whether an event is sent to Event Management whenever a communication set (one or more IFDs) was not sent to the destination application and the event is not placed in the send error (SE) status.

You can configure the following DETAILS field for this policy:

-   **Return Number 1**: Specifies whether the policy is enabled. A value of 1 is enabled, 0 is disabled. The policy is enabled by default.
